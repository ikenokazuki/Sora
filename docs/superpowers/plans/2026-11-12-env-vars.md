# 環境変数の整理（v5.0.0）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sora が読む環境変数の名前・値の読み方・検査を、設計（`docs/superpowers/specs/2026-11-11-env-vars-design.md`、承認済み、#72）のとおりにそろえる。
**Architecture:** 変数の登録簿と読み取りの関数を `src/config.ts` に集め、各領域の読み取りをそこ経由にして名前を変える。旧名は別名として読まず、起動時の検査（`checkEnv`）で、旧名だけが設定されているときに拒否または警告する。旗の廃止・実験のコードの削除・不具合の修正・README §4.3 の生成・移行の表までを、領域ごとの作業で進める。
**Tech Stack:** Bun、TypeScript。テストは `bun test`。

## Global Constraints

- 名前・領域・既定・型・「旧名だけのとき」の扱い・値の読み方・起動時の検査・直す不具合は、設計メモが正本（「対応表」「値の読み方」「起動時の検査」「直す不具合」）。この計画は、順序と、各作業の範囲と、設計メモの後に増えた 3 個を足す。
- **設計メモの後に main に入った変数 3 個を、登録簿に足す**（どれも名前は命名の決まりに合う。KEEP）: `SORA_BROWSER_LOW_MEMORY`（BROWSER、真偽値、既定 false。`src/browser_engine.ts` の `isBrowserLowMemory(env)` が呼び出しのたびに読む）、`SORA_FETCH_TRUST_STORE`（FETCH、列挙 `combined`・`mozilla`・`defaultPaths`、未設定は wreq-js の既定。`src/http_fetcher.ts` の `getOrCreateHttpSession` が `src/tls_trust.ts` の `parseTrustStoreMode` で呼び出しのたびに読む。公開イメージは Containerfile の `ENV` で `defaultPaths`）、`SORA_FETCH_MAX_CHROME_PROFILE`（FETCH、整数。3 桁の 10 進数で 136 以上、既定 149。`src/http_fetcher.ts` が**モジュールの読み込み時に** `parseMaxChromeProfile` で読む。公開イメージは Containerfile の `ARG WREQ_MAX_CHROME_PROFILE` から `ENV` で 154。下げれば挙動を戻せる設計なので、README の説明は残す）。登録簿の `SETTINGS`（Sora 固有の設定）は、設計メモの 53 個 + この 3 個 = 56 個、`EXTERNAL`（標準の名前）は 13 個。設計メモの「74 個」は、設定でないもの 8 個（`SORA_VERSION`・`SORA_MCP_INSTRUCTIONS`・`SORA_GCC_` の接頭辞・`PATH`・`LOCALAPPDATA`、テスト・スクリプト用の `SORA_LIVE_TESTS`・`SORA_TOOL_HEALTH_CASES_JSON`・`SORA_URL`）も数えた数（53 + 13 + 8）。登録簿の件数は、実装で数えて、設計メモの対応表と一致させる。
- **計画のあとに main に入った変数 5 個も、登録簿に足した**（2026-11-12 追記。#93・#95 の BROWSER 3 個と、#99 の EGRESS 2 個。どれも KEEP）: `SORA_BROWSER_PIPE`（真偽値、既定なし。未設定は Bun の版で決める。`browserCdpMode` が起動のたびに読む）、`SORA_BROWSER_UID`（文字列 `auto`・`off`・正の整数、既定 `auto`。形は `pattern`、範囲の上限は起動のときの警告）、`SORA_BROWSER_SANDBOX`（列挙 `auto`・`on`・`off`、既定なし。`NODE_ENV=test` の未設定は `off`）。後ろの 2 つは `planBrowserLaunch` が起動のたびに `envRaw` で読み、不正な値の警告は計画の側に残す（起動時の検査は、不正な値を止める）。このため `envBool` は、既定の無い設定では、未設定・不正のとき `undefined` を返す（「自動」を表す。既定のある設定は変わらない）。`SETTINGS` は 61 個。EGRESS の 2 個は、新しい領域 `egress`（`AREAS` の PROXY の次）に足した: `SORA_EGRESS_GATEWAY`（真偽値、既定 off。書き方の誤りは起動のときに止める。`isEgressGatewayEnabled` は、起動の検査を通らない経路でも、不正な値を `envError` の文でエラーにする）、`SORA_EGRESS_PORTS`（ポートの列 1〜65535、登録簿の既定なし。未設定はゲートウェイの既定 80・443）。`getProxyConfig`（#99 で `src/net/proxy_config.ts` に移った）も、登録簿の読み口で読む。
- **読む時機は、いまのまま**: モジュールの読み込み時に読んでいる所（`PORT`・`MAX_CONCURRENT_BROWSERS`・`YAHOO_MCP_PATH`・FxTwitter のシングルトン・MCP のセッション管理・Origin の中間層・`SORA_FETCH_MAX_CHROME_PROFILE`）は、同じ時機のまま、getter を通すだけ。それ以外は、呼び出しのたびに `process.env` を読む（覚えない。テストが実行中に環境変数を書き換える性質を保つため）。
- **旧名を別名として読まない。** 旧名の短い一覧は `src/config.ts` の中だけ（`checkEnv` が使う）。ツール統合の「旧名の別名は残さない」と同じ。
- **テストの環境変数の名前の置き換えは、そのコードを直す作業と同じ作業の中で行う**（各作業の終わりに、全体テストが通る状態にする）。`docs/superpowers/` と `docs/evaluations/`（過去の記録）は書き換えない。
- 値の読み方は設計メモの「値の読み方（統一）」のとおり。呼び出しのたびの読み取りでは、不正な値は既定値を返し、例外を投げない。起動時だけ、不正な値を変数名と正しい形つきで止める（作業 7）。秘密の値は表示しない（「設定済み、長さ N」）。
- 動きを変えてよいのは、設計メモが決めたところだけ（`'1'`・`'yes'` が真になる、`SORA_MCP_DEFER_TOOLS` が `'0'`・`'off'` で無効になる、不正な値が起動時のエラーになる、旗の固定・実験の削除、不具合の修正）。それ以外は、既存のテストが、名前の置き換えだけで通ること。
- リクエストの引数（URL など）の長い文字列に正規表現をかけない、または、かけるなら線形になる形にする（長さの上限・固定の接頭辞）。作業 2 のレビューで、ログから URL を伏せる正規表現が 2 乗の時間になり、1 回のリクエストでサーバーが止まる穴になった。秘密を含む宛先の例外は、文（message）を出さず、`errorKind(err)`（code か name）だけを記録する。
- Sora は OSS。作者の個人のサービスや私的なシステムの名前を、コード・文書・コミット・リリースノートに書かない。例の値は架空のものを使う。
- コミットは `git -c user.name=ikenokazuki -c user.email=51224867+ikenokazuki@users.noreply.github.com commit` で、Co-Authored-By や Generated-with の行を付けない。コミットの本文に「skip ci」と書かない。`git stash`（引数なし）・`git checkout .`・`git clean` を使わない。`rm` は `"${VAR:?}"` の形で、確かめてから。push・PR・マージはしない（コントローラーが、ユーザーの確認のあとで行う）。git のネットワークのコマンド（fetch・pull・push）を実行しない。
- 手元でテストを回す条件: `env -u HTTPS_PROXY -u HTTP_PROXY bun test --timeout 60000`。全件（約 3,300 件・約 6 分）は、前景で回さず、`run_in_background` で。Chromium は、手元に入っているもの（`CHROME_PATH=<chromium の実行ファイル>`）を指す。
- 各作業の終わりに、次が全部通ること: `bun run typecheck`、`bun run lint`、`bun run schema:notation`（TOTAL 0）、`bun run gen:client`（実行後に `client/` の差分がコミット済みと同じ。変数名が `types.ts` の説明に入っていて差分が出たら、作り直してコミットする）、全体テスト。
