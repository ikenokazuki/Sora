# 住所の座標化と地震情報を公式データに寄せる

## 目的

第三者の無料サービスに頼っている 2 か所を、公的な一次データを先に引く形にします。

1. **住所の座標化**（`get_elevation`・`search_poi` の中心地名）: 外部の経路が Nominatim（OpenStreetMap の公開サーバー）を先に引き、国土地理院の住所検索は「該当なし」のときだけでした。
2. **地震情報**（`search_earthquake`）: P2P地震情報（有志の運営する中継）から取っていました。

使わないユーザーに負担をかけない方針（既定で何も起動・取得しない）は変わりません。どちらも呼ばれたときだけ問い合わせ、常駐の処理・保存はありません。

## 住所の座標化

### 変えること

外部の経路の順を、入力で変えます。

- 番地まである住所（「1-5-1」のように数字がハイフンでつながる、または数字に「丁目」「番」が付く）は、国土地理院の住所検索を先に引きます。該当が無いとき、または国土地理院が使えないときは、Nominatim に進みます。
- それ以外（地名・駅名・施設名）は、今までどおり Nominatim が先です。国土地理院は Nominatim が「該当なし」と答えたときだけです。Nominatim が HTTP エラーのときは、国土地理院に切り替えずエラーにします。
- 1.1 秒の間隔（Nominatim の利用規約）は、Nominatim への問い合わせにだけかけます。国土地理院への問い合わせは待たせません。

自前のデータ（ABR・郵便番号）で決まる入力は、今までどおり外部に出ません。

### 根拠（2026-11-11 の実測）

| 入力 | 国土地理院 | Nominatim |
|---|---|---|
| 東京都千代田区永田町1-5-1 | 0.12 秒・正解の 1 件 | 0.58 秒・0 件 |
| 渋谷駅 | 15 件（福島県や千葉県の「渋谷」） | 0.90 秒・正解（渋谷区の駅） |
| 東京タワー | 50 件（「東」で始まる別の地名） | 0.81 秒・正解 |

番地まである住所 8 件（東京・大阪・札幌・京都・福岡）を新しい順序で解決すると、8 件とも国土地理院が 0.1〜0.5 秒で正しい地点を返しました。施設名と駅名は国土地理院では当たらないので、番地の無い入力の順は変えません。

### 判断

- 番地を含むかは、正規表現で判定します（`looksLikeStreetAddress`）。ハイフン類は ASCII・全角・長音・各種ダッシュを許し、「国道246号」のような道路は含めません。
- 番地の無い入力で Nominatim が使えないときに国土地理院へ落とさないのは、部分一致で別の地名を返し、誤った場所を `needsVerification` の印つきで返すより、エラーのほうが安全だからです。

## 地震情報

### 変えること

気象庁の公式データ `https://www.jma.go.jp/bosai/quake/data/` を主にします。`list.json`（直近約 1 か月・約 200 報・約 160 件）と、各報の JSON を使います。

- 同じ地震（`eid`）の報（震度速報・震源に関する情報・震源・震度情報）は 1 件にまとめます。震源・震度情報が出るまでは、あるぶんの情報で返します（震源に関する情報があれば震源と津波、震度速報があれば最大震度）。
- 遠地地震（国外）は含めません。`minIntensity` は 10（震度1）以上なので、今までも既定では出ませんでした。
- 震源は `cod`（ISO 6709、高さの負が深さ）から、深さは km に直します。観測点は各報の JSON から、震度3以上を強い順に 10 件まで。
- 津波の欄は、気象庁の固定の文のコード（`0215` 心配なし、`0212` 若干の海面変動、`0217` 今後の情報に注意）を従来の言い回しにそろえ、知らないコードは気象庁の文をそのまま返します。
- 絞り込み（`minIntensity`）は一覧の全件に対して行います。P2P の 100 件より広く、約 1 か月ぶんを見ます。
- 各報の詳細は、返す件数（最大 20）だけ並列で取ります。津波と観測点を取り出した結果は、報の名前で 24 時間キャッシュします（報の中身は後から変わりません）。詳細が取れない地震は、観測点なし・津波は「津波の有無は不明（詳細を取得できませんでした）」で返します。
- 気象庁の一覧が取れない（HTTP エラー・形が違う）ときだけ、従来の P2P地震情報から返します。各件の `source`（`jma` / `p2pquake`）で分かります。両方失敗したら、両方の理由を書いたエラーにします（0 件にはしません）。
- 応答の形は変えません。`source` は、もともと `jma` を許していました。

### 根拠（2026-11-11 の実測）

- 本物の気象庁データで 20 件を取り、冷えた状態で 356ms、2 回目は詳細がキャッシュから来て速くなります。
- P2P地震情報と突き合わせると、20 件とも最大震度とマグニチュードが一致しました。
- 気象庁の `bosai` の JSON は公式の文書化された API ではなく、画面用です。実際、旧い警報の JSON は 2026-05 に止まっています（このため警報は r8 に移した）。P2P を退避先に残すのは、この理由です。
- 退避が起きても気づけるよう、実 API の検査（tool-health の `quake.latest`）は、答えの `source` が `jma` であることを確かめます。

## 範囲外

- Yahoo! の画面を読む機能（乗換・道路交通・フライト）は変えません。
- POI の OpenPOI は変えません（新機能の検討で、医療・避難所などの一次データを足す）。
- `GET /health?detailed=true` の `p2pquake` の疎通確認は、退避先の確認として残します。
