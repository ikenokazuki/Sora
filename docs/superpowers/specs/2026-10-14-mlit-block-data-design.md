# 国土交通省「街区レベル位置参照情報」の追加 設計

日付: 2026-10-14
状態: 実装済み（2026-10-14）。当初の設計から、§12 のとおり変えた点があります。
前提: [住所データ基盤の設計](2026-10-13-address-data-design.md)（実装済み）

## 1. 目的と範囲

デジタル庁 ABR だけでは番地・号に届かない住所を、国土交通省の街区レベル位置参照情報（以下 MLIT 街区データ）で補います。

届かない住所の例（Zenn の記事「日本のヤバい住所」の例を実データで試した結果）は次のとおりです。

- 大字の無い住所（御所市1-3）。ABR の町字は大字ごとで、大字なしの枠に番地がありません。
- 街区符号に仮名が入る住所（羽咋郡志賀町高浜町マ17-7、羽咋市柳田町ほ79-1 は地番として届くが、近傍の仮名の街区符号は ABR に無い場合がある）。
- 浦安市舞浜2-11 のように、住居表示と地番が混在する町。

範囲は次のとおりです。

- 含める: MLIT 街区データの取得・構築・正規化への反映、出典表示、事前取得との連携、検証。
- 含めない: 住居番号（街区の下の「号」）の補完（MLIT 街区データには無い）、行政区画のポリゴン判定、記事の「仮説ロジック」（データに無い番地を推測で補う処理）。

**期待する効果は、まだ測っていません。** 実装の前に、フェーズ 0 で実データを使って効果を測り、基準に満たなければ中止します（§9）。

## 2. 実測した事実（2026-10-14）

MLIT 街区データは、国土交通省の位置参照情報ダウンロードサービスで提供されています。

- URL は直接取得できます（認証なし）。
  - 都道府県単位: `https://nlftp.mlit.go.jp/isj/dls/data/24.0a/13000-24.0a.zip`
  - 市区町村単位: `https://nlftp.mlit.go.jp/isj/dls/data/24.0a/13101-24.0a.zip`（千代田区。5 桁の市区町村コード）
- 版は `24.0a`（最終更新 2026-07-07、2025 年版のデータ）。`25.0a`・`24.0b` は 404。毎年 1 回更新（国土交通省の説明）。過去の版（23.0a、22.0a、21.0a）も取得できます。
- 大きさ: 東京都 3.8MB、北海道 3.6MB、千葉県 6.9MB、大阪府 4.2MB、石川県 1.8MB、奈良県 1.8MB、宮崎県 1.4MB（zip）。千代田区の市区町村単位は 33KB。東京都の CSV は展開後 29MB、27.3 万行。
- 形式: Shift_JIS（CP932）の CSV。列は `都道府県名, 市区町村名, 大字・丁目名, 小字・通称名, 街区符号・地番, 座標系番号, Ｘ座標, Ｙ座標, 緯度, 経度, 住居表示フラグ, 代表フラグ, 更新前履歴フラグ, 更新後履歴フラグ`。
- **町や市区町村のコードを持たない**（名前だけ）。ABR の `machiaza_id` とは名前で結びつける必要があります（郵便番号の結びつけと同じ方式で、実測 97.3%）。
- **「号」を持たない**。街区符号（住居表示の町）または地番（住居表示でない町）の本番までです。1 行は 1 つの街区または地番の代表点です。
- 例: 御所市は「（大字なし）」の行が 1,498 行あります（ABR には無い）。浦安市舞浜は `舞浜`、`舞浜二丁目`、`舞浜三丁目` の 3 つの町名で入っています。

## 3. 設計の方針

1. **ABR が主、MLIT は補完。** 同じ町で同じ番号が両方にあるときは ABR を採ります。MLIT は ABR に無い町と番号だけを足します。
2. **既存の仕組みに乗せる。** 新しい成果物の種類は増やさず、市区町村の番地・号（段B の `num:<lg6>`）の構築ジョブが、MLIT の市区町村単位の zip も取得して、地番の節に足します。ライブラリの読み取り（仮想ファイル）は変えません。
3. **MLIT が落ちても ABR は動く。** MLIT の取得に失敗しても、段B は ABR だけで公開します。印（`mlit: "missing"`）を残し、次の再確認で取り直します。
4. **使わない人に負担をかけない。** 起動時の処理を足しません。取得は、その市区町村の段B を作るときだけです。1 市区町村あたり 33KB 前後の追加で、事前取得（`SORA_ADDRESS_PRELOAD`）の対象にも自動で含まれます。
5. **正確さを偽らない。** MLIT 由来の結果は、`numberSource: "mlit"` と、番地・号でなく街区までの照合であることを明示します。

## 4. 構成

### 4.1 取得（`address_mlit.ts`）

- 版の解決: 既知の最新版（定数 `24.0a`）から、次の年の版を先に試し（`25.0a`）、無ければ既知の版を使います。404 のときは 1 つ前の版へ戻します。結果は `master` の再確認と同じ頻度（30 日）でキャッシュします。
- 市区町村ごとに `{lg5}-{版}.zip` を取得し、CP932 の CSV を読みます（既存の `address_csv.ts` のストリーム処理と文字コード指定を再利用）。署名は版と ETag・サイズのハッシュです。
- 取得元に無い市区町村（404）は、MLIT なしとして正常に扱います（毎回調べ直さないため、`mlit: "none"` を残す）。

### 4.2 町の結びつけ

MLIT の `大字・丁目名` + `小字・通称名` を、ABR の町字（段A の `town.json`）の名前に結びつけます。

- 規則は郵便番号の結びつけ（`postal_code.ts`）を共通化して再利用します（NFKC、漢数字、「大字」「字」「丁目」の除去、ヶ・ケ・ノ・之などの揺れ）。
- 「（大字なし）」は、ABR の大字なしの町字（`machiaza_id` が `0000000` で名前を持たない枠）に結びつけます。ABR にその枠が無ければ、町を足さずに捨てます。
- 結びつかなかった行は捨て、件数をログに出します（結びつき率の目安は §9 の基準）。

### 4.3 地番の節への足し込み

- MLIT の街区符号・地番を、ABR の地番の節（`prc_num1,prc_num2,prc_num3,lng,lat`）と同じ形の行にします。本番だけを持つ行（枝番なし）です。
- 同じ町に ABR の行があれば、その本番と同じキーの MLIT の行は足しません。住居表示の町（`rsdt`）には、MLIT の街区符号を街区の節として足す案と足さない案があり、これは §10 の確認事項です（ライブラリは住居表示の町で地番を引かないため、足すには `rsdt` の節に街区だけの行を入れる必要がある）。
- 足した行の出所を、節の外の小さな索引（`mlit.json`: 町字ごとの MLIT 行の本番の一覧）で持ちます。正規化の結果が MLIT 由来かどうかを、これで判断します。

### 4.4 正規化の結果

- `numberSource` に `'mlit'` を足します。値の意味は「MLIT の街区データで街区または地番の本番まで照合した。号は未照合」です。
- `level` は 8 のままにせず、街区までを示す値にするかを §10 で決めます。既定案は、`level: 8` のまま `numberSource: "mlit"` と `point.level: 7`（街区の代表点）です。
- `keys` に `prc: [本番]` を入れます（地番と同じ形）。
- 出力に `attribution` を足します（§6）。

### 4.5 他の機能との関係

- **局所ジオコーダー**: `point.level < 8` の結果は従来の経路へ回す現行の規則のとおり、MLIT 由来の街区の点は使いません（配送の正確さを優先）。
- **逆ジオコーディング**: 初版では MLIT を使いません。ABR の点がある範囲を優先する現行の動作のままです（MLIT の点を候補に足すかは別の判断）。
- **突き合わせ**（`checks`）: `numberSource: "mlit"` の住所は、番地・号を照合できていないものとして、町字止まりと同じ扱いで比べます（`verified` にしない）。
- **事前取得**: 段B の構築に含まれるので、変更不要です。

## 5. 失敗と更新

- MLIT の取得に失敗しても、段B は ABR のみで公開し、`mlit: "missing"` を残します。次の再確認（段B の期限 30 日、または使われたとき）で取り直します。
- 版が上がったとき（年 1 回）は署名が変わるので、使われたときの再確認で作り直されます。
- 国外 IP の拒否の有無は、実測で確認します（この日本のホストでは取得できた）。拒否される場合は ABR と同じく `blocked` として扱います。

## 6. 出典と利用条件

- MLIT の説明: 位置参照情報は、出典を記載し、編集・加工した旨と利用したコンテンツの名称を併記します。国が作成したかのような公表は禁止です。記載例は「出典：位置参照情報ダウンロードサービス（国土交通省）（URL）」。公共測量などの高度な精度が必要な用途や各種証明には使えません。
- 追加する出典文言は `MLIT_ATTRIBUTION`（`address_attribution.ts`）に置き、MLIT 由来の結果にだけ `addressAttribution` で足します（地番の出典と同じ方式）。
- **未確認（フェーズ 0 で確認）**: 位置参照情報の利用約款（`agree-03`）の本文を取得できていません。商用利用、再配布、自動ダウンロードの可否が、確認できたページには書かれていません。国土交通省の一般的な方針（公共データ利用規約 第1.0版）であれば商用可ですが、本文で確認します。確認できなければ、問い合わせるまで実装を進めません。

## 7. テスト

- 単体: CSV の読み取り（CP932、引用符、空列）、町の結びつけ（実データの代表行を固定データにする）、足し込みの優先順位（ABR が勝つ）、`mlit.json`、版の解決。
- 結合: 偽の取得元で段B を構築し、正規化で `numberSource: "mlit"` になること、MLIT が 404・403・失敗のときに ABR だけで公開されること、出典が付くこと。
- ツール: tool-health の住所ケースに MLIT 由来の例を足すかは、フェーズ 0 の結果で決める。
- すべて通信なしの固定データ。実データでの確認は手動で行い、結果を運用手引に記録します。

## 8. 実装の段階

0. **スパイク（効果の測定）**: 実データで、(a) 利用約款の本文の確認、(b) 記事の 31 例で、MLIT を足すと番地まで届く件数、(c) 代表的な 10 都道府県での結びつき率と、MLIT にしか無い街区の割合、(d) ライブラリが「大字なし」の町と、街区だけの節をどう扱うか、(e) 仮名の街区符号（マ17、ほ79）が MLIT に入っているか。
1. 取得と構築（`address_mlit.ts`、段B への足し込み）。
2. 正規化・出力（`numberSource`、`point.level`、`keys`）と出典。
3. 突き合わせ・ツール説明・スキーマ・運用手引の更新。
4. 実データでの検証と、結果の記録。

各段階の終わりで、型検査・lint・関連テストが通る状態にします。

## 9. 完了条件と中止の基準

- フェーズ 0 の結果で、記事の 31 例のうち、現在届かない例が **3 件以上** 番地または街区まで届くと見込めること。見込めなければ中止し、結果を仕様書に残す。
- 町の結びつき率が、測った都道府県で **90% 以上**（郵便番号の結びつけの実測は 97.3%）。
- 段B の構築時間の増加が、1 市区町村あたり **0.5 秒以内**（取得 1 回と CSV の解析）。
- 既存のテストが変わらず通り、MLIT が使えないときの出力が現在と同じであること。

## 10. 決めてほしいこと

1. 利用約款の本文を確認できない場合に、国土交通省へ問い合わせるか、公共データ利用規約 第1.0版に従うと判断して進めるか。
2. 街区までの照合を `level: 8` + `numberSource: "mlit"` + `point.level: 7` で表すか、新しい level の値を足すか（既定案は前者。既存の利用側への影響が小さい）。
3. 住居表示の町にも、MLIT の街区符号を足すか（既定案は足さない。ABR の住居番号が主で、街区だけの結果は精度が下がるため）。
4. 局所ジオコーダーが街区レベルの点を使うか（既定案は使わない）。

## 11. リスク

- 結びつき率が低い町（名前の揺れ、合併前の名称）があると、効果が小さい。フェーズ 0 で測る。
- MLIT の版の URL が将来変わる。版の解決は 404 で検知し、既知の版へ戻る。年 1 回の更新で壊れた場合は、`unavailable` と印で見える。
- ライブラリが街区だけの節や名前の無い町を想定していない可能性。フェーズ 0（d）で確認し、不可なら足し込みの形を変える。
- 保守: 年 1 回の版の更新を、定数の更新ではなく探索で吸収する。運用者の作業は増えない設計にする。

## 12. 実装結果（2026-10-14）

決定: 利用条件は公共データ利用規約 第1.0版に従うと判断して進める（§10-1）。§10 の 2〜4 は既定案のとおり。

**設計から変えた点**

- 当初は「段B の構築に足し込む」案でしたが、実装前の確認で、Geolonia ライブラリが番地・号を**完全一致**（`7-1` のような最大3つの数字の並びが、データの1行と等しいこと）でしか照合しないと分かりました。街区符号だけの行（`10`）は、入力が `10-18-3F` のように続くと一致しません。そのため、ライブラリには足さず、**正規化の後処理**にしました。
- 成果物は独立の `mlit:<lg_code>`（`index.json`）にしました。MLIT の障害が ABR の段B に影響しません。
- 町の結びつきは `machiaza_id` ではなく**名前の折りたたみ**（郵便番号の結びつけと同じ `foldName`）で、ライブラリが返した町名と MLIT の「大字・丁目名＋小字・通称名」を比べます。「（大字なし）」は空の町名と比べます。街区符号が仮名・英字で始まる行（`マ17`）は、町名に仮名を足した別名（`高浜町マ` → `17`）でも引けるようにしました。半角カナは NFKC で全角にそろえます。
- 市区町村単位の zip は、CSV のほかに HTML と XML を含み、順序が一定でないため、CSV を名前で選ぶ必要がありました（最初のファイルを読む実装では、一部の市区町村で空になりました。実データの確認で見つけて直した）。

**フェーズ 0 の確認と完了条件**

- 記事の 31 例: ABR だけで番地・号に届いたのは 12 件でしたが、街区データを足すと **27 件**になりました。新たに届いた例は、芝大門、舞浜（二丁目11）、下田市2丁目、八街は18、御所市1-3、上町A、久太郎町渡辺、志賀町高浜町マ17、南長野県町、鹿児島市中央町、大和大路、府中市（2か所）、葦北・芦北です。届かないのは、ABR にも街区データにも無い `ケ1-8`、「京都市」が抜けた入力、「条」を漢数字で書いた札幌の入力です。完了条件（3 件以上）を満たしました。
- 段B に足す構築時間の増加: 市区町村1件あたり、HEAD 数回と zip 1つ（33KB〜数百KB）の取得と解析で、実測で約 0.3〜1 秒（最初の呼び出しの体感は約 4 秒で、ABR の段A・段B の構築を含む）。
- 町の結びつき率の網羅的な測定はしていません。上の 31 例では、街区データのある例のうち、結びつかなかった例はありませんでした。
