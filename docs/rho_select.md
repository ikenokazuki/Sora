## 1. 3分でわかる！初心者向け直感解説

### LLMにWebページを読ませる際の「壁」

AIエージェント（ChatGPTやClaudeなど）にWeb検索やページの内容を読ませて質問に答えさせるとき、開発者を悩ませる大きな問題が3つあります：

1. **トークンの無駄遣い（API料金が高くなる）**:  
   Webページは長大です。ヘッダー、サイドバー、広告、規約、関連リンクなどが大量に含まれ、1ページで1万〜5万文字（数千〜数万トークン）に達することが珍しくありません。
2. **回答が遅くなる（レイテンシの増大）**:  
   LLMに何万文字もの文章を一度に読ませると、最初の文字が出力されるまでの待ち時間が数秒〜十数秒も伸びてしまいます。
3. **肝心な情報を見落とす（Lost in the Middle / ハルシネーション）**:  
   LLMは、長すぎる文章の真ん中あたりに書かれた重要な事実を見落としやすいという性質（*Lost in the Middle* 現象）を持っています。その結果、適当な嘘（ハルシネーション）をついてしまう原因になります。

---

### 従来のハイライト抽出が抱えていた弱点

「じゃあ、キーワードが含まれる大事な段落だけを切り抜いてLLMに渡せばいいのでは？」と考えるのが自然です。  
しかし、従来の「キーワードマッチスコアが高い順に上位3つを選ぶ」という単純な方法には、大きな落とし穴がありました：

- **同じことの繰り返し（情報の重複）**:  
   クエリが「東京ドーム チケット 料金」だった場合、1位の段落も2位の段落も「東京ドームのチケット料金は〜」と似たような文であると、2つ選んでも新しい情報が増えません。
- **長すぎる文章の過大評価（コスパの悪さ）**:  
   1000文字もあるダラダラした長い記事は、キーワードがたくさん登場するためスコアが高くなりがちです。しかし、たった50文字で「料金：一般3,000円」とズバリ書かれている短い表のほうが、LLMにとっても人間にとっても遥かに価値があります。

つまり、**「どれだけ情報が含まれているか（効用）」** だけでなく、**「どれだけ文字数（トークン数）を節約できたか（コスト）」** の**コストパフォーマンス（情報密度）**を最大化しなければなりません。

---

### ρSelect のアイデア：お得な「バイキング（食べ放題）」の例え

$\rho$Select（ロー・セレクト）は、この問題を**「お得なホテルのバイキング料理選び」**のように数学的に解くアルゴリズムです。

```
【ホテルバイキングの例え】
・入場料（τ）: 960円（必ずかかる基本料金 ＝ LLMのプロンプト基本トークン）
・お皿に乗せられる料理: 最大3品まで（K = 3）
・あなたの目的: 「支払った合計金額（入場料 ＋ 料理ごとのカロリー代）」に対して、
               「食べた料理の満足度（効用）」の割合を最大にすること！
```

1. **満足度の「お腹いっぱい（飽和）」ルール**:  
   「ステーキ（キーワードA）」を1つ取ったら満足度は大満足です。そこへさらにもう1つステーキを追加しても、満足度はほとんど増えません。次は「デザート（キーワードB）」を取ったほうが、全体の満足度がぐんと高くなります（数学用語で**「劣モジュラ性（収穫逓減）」**と呼びます）。
2. **入場料 $\tau$（タウ）の大事な役割**:  
   もし入場料（$\tau$）がゼロだと、「ミニトマト1個（コスト極小、満足度そこそこ）」だけを食べて帰るのが最もコスパが良い、というおかしな結論（**Singleton 退化**）になってしまいます。  
   「最初に入場料 $\tau$ を払っているのだから、ある程度しっかり満足できる組み合わせを選んだほうがお得だよね！」とアルゴリズムが賢く判断できるように調整するのが $\tau$ です。

$\rho$Select は、この**「満足度 $\div$ （基本料金 ＋ 文字数コスト）」という分数の密度を、数学的に100%厳密に最大化するセクションの組み合わせ**を、わずか **1.5ミリ秒（0.0015秒）** という超高速で計算して選び出します。

## 2. 数学的に丁寧な理論解説

本章では、$\rho$Select の数学的定式化、劣モジュラ性、基数制約、有界疎動的計画法、Paretoフロンティア走査、および Dinkelbach 法検証器について体系的に解説します。

### 問題の定式化と目的関数

入力文書を $N$ 個の互いに素な候補セクションの集合 $V = \{s_1, s_2, \dots, s_N\}$ とします（各 $s_i$ はMarkdownの見出し階層または補完証拠ブロック）。  
ユーザーの検索クエリ $Q$ に対し、選択する部分集合を $S \subseteq V$、最大採択件数を $K$（基数上限）とするとき、$\rho$Select は以下の**制約付き分数最適化問題（Bounded Fractional Submodular Maximization）**を解きます：

$$\max_{S \subseteq V,\; |S| \le K} \rho_\tau(S) = \frac{U(S)}{\tau + C(S)}$$

---

### 変数の数理的定義と役割

| 記号 | 名称 | 数学的性質 | 定義と役割 |
| :--- | :--- | :--- | :--- |
| $V$ | 候補セクション集合 | 有限離散集合 $|V|=N$ | Markdown見出し構造から抽出されたセクション群、およびスニペット等の補完証拠ブロック。 |
| $S$ | 採択セクション集合 | $S \subseteq V, |S| \le K$ | LLMへハイライトとして渡すために選ばれたセクションの組み合わせ。 |
| $K$ | 基数制約上限 | 正の整数 ($K \ge 1$, 規定値: 3) | 抽出する最大ハイライト件数。コンテキストの散漫化を物理的に防止する。 |
| $c(s_i)$ | セクションコスト | 正の有界値 $c(s_i) \ge 1$ | 当該セクションの推定消費トークン数（`estimateTokens(s_i)`）。 |
| $C(S)$ | 集合コスト関数 | **厳密な加法関数** | $C(S) = \sum_{s \in S} c(s)$。選ばれた全セクションの総トークン数。 |
| $U(S)$ | 効用関数 | **正規化・単調・劣モジュラ関数** | クエリに対する証拠網羅度・適合度を表す効用。 |
| $\tau$ | 固定オーバーヘッド | 正の定数 ($\tau \ge 1$, 規定値: 96) | プロンプト指示文やシステムメタデータに伴う不変の基準トークンコスト。 |
| $\rho_\tau(S)$ | シフト付き関連密度 | 目的関数（分数） | トークン消費1単位あたりに獲得できる情報効用の密度。 |

#### 効用関数 $U(S)$ の劣モジュラ性（Submodularity）:
任意の $A \subseteq B \subseteq V$ および $s \in V \setminus B$ に対し、以下が成立します：
$$U(A \cup \{s\}) - U(A) \ge U(B \cup \{s\}) - U(B)$$
すなわち、すでに多くのセクションを選択している状態（$B$）に新たなセクション $s$ を追加したときの効用の増加分（限界効用）は、まだあまり選択していない状態（$A$）に追加したときの限界効用以下となります。これにより、同一クエリ語の冗長な重複が自動的に抑制されます。

---

### 固定オーバーヘッド $\tau$ の数学的意味（Singleton Degeneracy の解消）

もし $\tau = 0$ と置いた場合、目的関数は単純な比率 $\frac{U(S)}{C(S)}$ となります。  
このとき、もし「文字数が極端に小さく（例: 2トークン）、クエリ語を1単語だけ含む極小の断片 $s_{\text{tiny}}$」が存在すると、$\frac{U(\{s_{\text{tiny}}\})}{c(s_{\text{tiny}})}$ が非常に大きな値を取り、**総合的に重要な情報を網羅する複数セクションの組み合わせが完全に排除され、ゴミのような極小断片1個だけが選ばれる現象（Singleton Degeneracy）**が発生します。

$\rho$Select では、正の固定パラメータ $\tau > 0$（デフォルト: $\tau = 96$）を分母に導入することで、以下の数学的定理を保証しています：

> **【定理：$\tau$ の単調性（Monotonicity under Overhead Shift）】**  
> $0 < \tau_1 < \tau_2$ とする。$\tau_1$ における最適解を $S_1^*$、$\tau_2$ における最適解を $S_2^*$ とするとき、
> $$C(S_1^*) \le C(S_2^*)$$
> が成立する。すなわち、固定オーバーヘッド $\tau$ を大きく設定するほど、アルゴリズムはより多くの証拠を含む相補的な複数セクション（より大きな総コスト $C(S)$）を採択する方向に滑らかにシフトする。

---

### 特徴束（Feature Lattice）と段階的証拠量子化

クエリ $Q$ から抽出された単語項 $T = \{t_1, t_2, \dots, t_m\}$（$m \le 6$）に対し、各セクション $s_i$ の適合度を単なるブール値ではなく、**Canonical BM25+ / BM25F** に基づく局所スコア $e(s_i, t)$ として計算します：

1. **見出し・本文のフィールド別正規化頻度**:
   $$\tilde{tf}(s_i, t) = w_H \cdot \frac{tf_H(s_i, t)}{1 - b_H + b_H \frac{\text{len}_H}{\overline{\text{len}}_H}} + w_B \cdot \frac{tf_B(s_i, t)}{1 - b_B + b_B \frac{\text{len}_B}{\overline{\text{len}}_B}}$$
2. **BM25+ Term Evidence**:
   $$e(s_i, t) = \text{IDF}(t) \cdot \left( \frac{(k_1 + 1)\tilde{tf}(s_i, t)}{k_1 + \tilde{tf}(s_i, t)} + \delta \right)$$
   ここで $\delta = 0.8$ は短文・スニペットが不当にゼロ埋めされるのを防ぐ下限保証パラメータです。
3. **段階的量子化（Graded Quantization, $L$ レベル）**:
   各クエリ語の最大エビデンス $\max_{i} e(s_i, t)$ に対し、$L$ 段階（デフォルト $L=2$）の閾値特徴ビットを割り当てます。
   さらに、「完全フレーズ一致（Exact Phrase）」および「最新性インテント（Recency Intent）」のブール特徴を上位ビットに統合し、全体で $b \le 18$ ビットの特徴空間 $\mathcal{F}$ を構成します。
4. **マスクの効用**:
   特徴 $f \in \mathcal{F}$ の重みを $w_f$ とするとき、部分集合 $S$ の効用は被覆された特徴の線形和として閉形式で求まります：
   $$U(S) = \sum_{f \in \mathcal{F}} w_f \cdot \mathbb{I}\left( \exists s \in S \text{ s.t. } s \text{ satisfies feature } f \right)$$

---

### 厳密解法：劣モジュラ有界動的計画法と Pareto フロンティア走査

一般の分数劣モジュラ最大化は NP 困難ですが、実務における検索クエリの語数は短く（$m \le 6$、特徴ビット数 $b \le 18$）、セクション数 $N$ も高々数百程度です。$\rho$Select はこの**クエリ有界性（Query-Bounded Property）**を利用し、ヒューリスティックな近似ではなく**厳密な大域的最適解（Exact Global Optimum）**を決定論的に導出します。

```
[ 入力セクション群 V ] (N個)
         │
         ▼
[ Dominance 前処理 ] ───► 同一 feature mask 内の最小コスト候補のみを残す (Compact Candidates)
         │
         ▼
[ Exact Sparse DP on (mask, count) ] ───► 状態 (M, k) に対する最小トークンコストを動的更新
         │
         ▼
[ Pareto 非支配フロンティア抽出 ] ───► (コスト C, 効用 U) の二次元空間で非支配解のみを抽出
         │
         ▼
[ Direct Optimum 走査 ] ───► ρ_τ(S) = U / (τ + C) を評価し、大域的最高密度の S* を確定
         │
         ▼
[ Dinkelbach 法 検証器 ] ───► exactAgreement: true を数学的に照合
```

#### ① Dominance 前処理 (Dominance Preprocessing)
同一の feature mask $M$ を満たす候補セクションが複数存在する場合、トークンコスト $c(s)$ が真に最小のものだけを 1 つ残し、他をパージします。これにより、DPで探索すべき候補数を劇的に圧縮します。

#### ② 基数保持 疎動的計画法 (Exact Sparse DP on $(mask, count)$)
状態を `key = (mask, count)`（被覆した特徴ビットマスク $M \in [0, 2^b - 1]$、選択済み件数 $k \in [0, K]$）としてハッシュマップ上で疎（Sparse）に展開します。
- **状態遷移**:
  現在の状態 $(M, k)$ に新たなコンパクト候補 $s$（マスク $M_s$、コスト $c_s$）を追加するとき：
  $$\text{NextKey} = (M \mid M_s,\; k + 1)$$
  $$\text{NextCost} = \text{Cost}(M, k) + c_s$$
  もし $\text{NextCost} < \text{ExistingCost}$ であれば状態を更新し、バックトラック用のインデックス配列を記録します。
- **計算量保証**:
  状態空間の最大サイズは $K \cdot 2^b$ に厳密に制限されます（$K=3, b=12$ のとき最大 $3 \times 4096 = 12,288$ 状態）。

#### ③ コスト–効用 Pareto 非支配フロンティア抽出
DPによって到達可能なすべての状態から、空集合を除く結果集合を抽出し、コスト昇順にソートします。
コストが増加しても効用が増加しない劣後解をパージし、**Pareto 最適な非支配フロンティア $\mathcal{P} = \{ (C_1, U_1), (C_2, U_2), \dots \}$** を構成します。

#### ④ Direct Optimum 走査
Pareto フロンティア $\mathcal{P}$ 上の各要素に対して目的関数値：
$$\rho_\tau(S) = \frac{U(S)}{\tau + C(S)}$$
を直接計算し、最大値を与える要素 $S^*$ を一意に選択します（タイブレーク時は効用大 $\to$ コスト小 $\to$ 件数少 $\to$ 先頭インデックス小の順で決定論的に解決）。

---

### Dinkelbach法（分数計画法検証器）との整合性

分数計画法（Fractional Programming）の古典的な標準解法である **Dinkelbach 法**（パラメトリック反復法）を内部検証器（Verifier）として組み込んでいます。
Dinkelbach 法は、パラメータ $\lambda \ge 0$ に対する線形化副問題：
$$F(\lambda) = \max_{S \in \mathcal{P}} \Big( U(S) - \lambda (\tau + C(S)) \Big)$$
を解き、$F(\lambda) \to 0$ となるまで $\lambda^{(t+1)} = \frac{U(S^{(t)})}{\tau + C(S^{(t)})}$ をニュートン法的に反復更新します。

$\rho$Select は毎実行時に Direct Optimum の解と Dinkelbach 法の収束解が厳密に一致することを照合し、診断量 `exactAgreement: true` を返却します。

## 3. 具体例による数値計算トレース（Step-by-Step）

本番稼働時に観測された実例（アーティスト情報の探索）を用いて、計算の推移を追跡します。

### 対象クエリと候補セクションの設定

- **クエリ**: `"君と見るそら 内山優花 作詞"`
- **固定パラメータ**: $\tau = 96$, $K = 3$, $L = 2$

抽出されたセクション候補（抜粋）：
- **セクション $s_1$（長文のライブスケジュール本文）**:
  - 内容: CLUB CITTAでのライブ出演時間、チケット料金、特典会情報...
  - トークンコスト: $c(s_1) = 210$ トークン
  - 含有クエリ語: `「君と見るそら」` のみ
  - 獲得効用: $U(\{s_1\}) = 1.20$
- **セクション $s_2$（別メンバーのインタビュー本文）**:
  - 内容: シングルリリースの感想、ダンスの振り付けの苦労...
  - トークンコスト: $c(s_2) = 180$ トークン
  - 含有クエリ語: `「君と見るそら」「内山優花」`
  - 獲得効用: $U(\{s_2\}) = 2.50$
- **セクション $s_3$（補完証拠：検索スニペット）**:
  - 内容: `内山優花プロデュース曲『季節外れのリナリア』 作曲:michitomo 作詞:内山優花(君と見るそら)`
  - トークンコスト: $c(s_3) = 38$ トークン
  - 含有クエリ語: `「君と見るそら」「内山優花」「作詞」`（**全クエリ語を網羅！**）
  - 獲得効用: $U(\{s_3\}) = 4.80$

### 単独選択 vs 複数選択の密度比較

各組み合わせにおける目的関数値 $\rho_\tau(S) = \frac{U(S)}{\tau + C(S)}$ を計算します（$\tau = 96$）：

| 選択パターン $S$ | 総トークン $C(S)$ | 総分母 $(\tau + C(S))$ | 獲得効用 $U(S)$ | 密度 $\rho_\tau(S)$ | 判定・解説 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **A. $S = \{s_1\}$ (ライブ本文のみ)** | 210 | $96 + 210 = 306$ | 1.20 | **0.0039** | 「作詞」が含まれず低効用かつ高コスト。 |
| **B. $S = \{s_2\}$ (インタビューのみ)** | 180 | $96 + 180 = 276$ | 2.50 | **0.0090** | 「作詞」が欠けており密度が低い。 |
| **C. $S = \{s_3\}$ (検索スニペット)** | **38** | $96 + 38 = 134$ | **4.80** | **0.0358** | **★ 最高密度（最適解）**<br>全クエリ語を網羅し、極めてコンパクト。 |
| **D. $S = \{s_3, s_2\}$ (スニペット＋インタビュー)** | 218 | $96 + 218 = 314$ | 4.85 | **0.0154** | すでに $s_3$ で全タームが満たされているため、追加効用はわずか $+0.05$。分母だけが $+180$ 膨らみ、**密度は半減以下に急落**。 |

従来の「キーワードを含むものを上から3つ詰め込む」ヒューリスティック手法では、パターン D やパターン A+B+C のように無駄な長文が大量に抱き合わせで選出されてしまいます。  
一方、$\rho$Select は有界分数最適化によって、**「すでに必要な情報が完璧に揃っているなら、無駄な長文を追加してトークンを浪費しない」** という判断を数学的に下し、パターン C（最高密度 0.0358）を自信を持って第1位ハイライトとして選出します。

## 4. システム実装と工学的工夫

$\rho$Select は理論の美しさだけでなく、本番環境で確実にミリ秒動作するための実用工学が組み込まれています。

### Markdown見出しスタックとコードブロック保護
- **見出し階層パンくず（Breadcrumb Context）**:  
  Markdownをパースする際、H1〜H6 の見出しレベルをスタックで管理し、`## 親見出し > ### 子見出し` というパンくず文字列を各段落に自動付与します。これにより、本文中に主語が書かれていなくても「どの製品・どのアーティストの話か」という文脈が欠落しません。
- **リスト内見出し階層認識（`- ### [記事見出し]`）**:  
  ポータルサイトやニュース一覧ページ（朝日新聞トピックス、Yahoo!ニュース等）で頻出する、箇条書きリスト要素内に埋め込まれたMarkdown見出し記号を正確に境界認識。一覧記事の各トピックを独立した候補セクション $s_i$ として精密に分離します。
- **Frontmatter・ナビゲーション等のボイラープレート自動排除**:  
  記事先頭の YAML frontmatter（`--- publishedTime: ... ---`）やパンくずメタデータ文字列（`> 📍 **階層**: ...`）等のボイラープレートが候補セクションに混入して選出を歪めるのを防ぎ、真に有用な本文記事コンテンツのみをスコアリング対象とします。
- **コードブロックの不可分保護**:  
  ` ``` ` で囲まれたコードブロック内部に存在する `#`（Pythonのコメント記号やC#のシンボル等）を見出し記号と誤認識しないよう、ステートマシンで厳格に隔離保護します。

### Intl.Segmenter によるスペース不要の日本語形態素抽出
- 外部の巨大な形態素解析辞書（MeCabやJuman等）を一切ロードせず、JavaScript標準の `Intl.Segmenter`（`granularity: "word"`）を活用。
- 「君と見るそら」「内山優花」のようにスペースで区切られていない日本語の固有名詞・複合語をゼロオーバーヘッド・高精度にトークナイズします。

### 補完証拠（検索スニペット・ディスクリプション）の動的統合
- X（旧Twitter）などのログイン保護ページやSPAサイトでは、スクレイプされた本文Markdownに直近の別ツイート一覧しか残っておらず、検索エンジンが捉えていた個別ポストの本文が脱落することがあります。
- $\rho$Select は、検索APIが返した `snippet` やメタタグの `description` を「見出しのない独立セクション」として候補プール $V$ に自動合流させます。本文に証拠がなくても、スニペットから最高密度のハイライトを救出できます。

### W3C Text Fragment によるブラウザ連動
- 選出されたハイライト文字列から、W3C標準規格である **Scroll to Text Fragment（`#:~:text=...`）** のURLを決定論的に自動生成します。
- これにより、エージェントやユーザーがブラウザでURLを開いた瞬間に、該当の証拠位置へ自動スクロール＆黄色ハイライト表示されます。

## 5. 今後の研究課題と予定されている拡張

$\rho$Select は現在も活発に開発が進められているプロトコルです。以下の論点について今後アップデートが予定されています：

1. **コンテキスト長に応じた $\tau$ の動的適応（Dynamic Overhead Scaling）**:  
   現在は固定値（$\tau = 96$）を標準としていますが、クライアントLLMのコンテキストウィンドウ長（4k / 32k / 128k / 1M）やタスク種別（要約 vs ピンポイント事実確認）に応じて $\tau$ を動的にスケーリングする機構の検証。
2. **テーブルセル（GFM Table）の細粒度空間束縛**:  
   表構造全体を1つのセクションとして扱うだけでなく、ヘッダー列と行の交差セル単位で部分抽出を行うマイクロ構造最適化。
3. **継続的なベンチマーク評価**:  
   多様な多言語ドキュメント、技術仕様書、法令文書等における情報保持率とトークン削減率の学術的測定。
