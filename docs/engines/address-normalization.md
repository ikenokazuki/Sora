# 日本語の住所を正規化する

日本語の住所を、都道府県・市区町村・町字（ちょうあざ）・番地・号に分け、公式のデータで裏づけて、結合に使えるキーと代表点の座標を付ける処理です。住所の書き方は、全角と半角、「1丁目7番1号」と「1-7-1」、漢数字、先頭の〒、建物名の有無など、ばらばらです。文字列のままでは、同じ場所の住所が同じに見えません。Sora は、文字列の解析を OSS のライブラリに任せ、答え合わせと補完には手元に取得した公式データを使います。2 つの住所が同じ場所を指すかの判定（名寄せ）と、郵便番号・座標との突き合わせもできます。

用語です。

- **ABR**: デジタル庁の「アドレス・ベース・レジストリ」です。町字、住居表示、地番などの公式データを公開しています。
- **町字**: 大字・丁目・小字などの町の単位です。ABR は町字ごとに ID（`machiazaId`）を持ちます。
- **住居表示**: 「永田町一丁目7番1号」のような、街区符号と住居番号による表し方です。
- **地番**: 土地ごとの番号です。住居表示を実施していない町では、地番が番地の代わりになります。
- **level**: 住所をどこまで読めたかの段階です。0 は都道府県も不明、1 は都道府県、2 は市区町村、3 は町字、8 は番地・号です。

## 使うツール

- MCP: `normalize_address`
- REST: `POST /geo/address/normalize`、`GET /geo/address/normalize`

引数は、`address`（必須、300 文字まで）、`level`（正規化する最大の段階。1 から 8、既定 8）、`zipcode`（突き合わせる郵便番号）、`lat` と `lon`（突き合わせる座標。組で指定）、`compareAddress`（名寄せの相手の住所）です。

住所のツールは、使われたときだけデータを取得します（`SORA_ADDRESS` が `lazy`、既定）。`SORA_ADDRESS=off` ではツールを登録せず、REST は 404 を返します。この処理は、郵便番号の逆引き（[postal-code.md](postal-code.md)）と座標の解決（[coordinate-resolution.md](coordinate-resolution.md)）の中でも使われます。

## 手元のデータと外への問い合わせ

Sora は、次のデータを自分のディスクに持ちます（保存先は `SORA_ADDRESS_DIR`、予算は既定 2GB）。

| 名前 | 中身 | 取得元 |
|---|---|---|
| 全国マスター | 都道府県と市区町村（約 1,900 件）の名前・コード・代表点 | ABR |
| 町字（段A） | 市区町村ごとの町字の名前と代表点 | ABR |
| 番地・号（段B） | 市区町村ごとの住居表示と地番の点 | ABR |
| 街区 | 市区町村ごとの街区符号の点 | 国土交通省の街区レベル位置参照情報 |
| 郵便番号 | 郵便番号と町域 | 日本郵便 |

既定では、使われるまで何も取得せず、使われた市区町村の分だけ取得します。全国一括では取得しません。運用者が `SORA_ADDRESS_PRELOAD` を指定したときだけ、起動の 10 秒後から指定した範囲を先に取得します。取得は別の子プロセスで行い、確認日時が期限を過ぎたものは、使われたときに裏で取得元の更新の印（ETag）と更新日時を確かめます。変わっていれば作り直します。期限は、町字と郵便番号が 7 日、それ以外が 30 日です。運用の詳細は [address-data.md](../operations/address-data.md) にあります。

利用者の要求に答えている間に外へ問い合わせるのは、データがまだ無い市区町村を初めて使うときだけです。取得が待ち時間（既定 20 秒）に間に合わなければ、取れている範囲で答え、取得は裏で続けます。データがあれば、外には出ません。外部のジオコーディングのサービスは使いません。ABR の配信元は、日本国外の IP からの接続を拒否することがあります。

## 決め方

1. 先頭の郵便番号（〒の有無、ハイフンの有無、全角を許す）を分けます。空の住所と、300 文字を超える住所は入力の誤りです。郵便番号だけの入力は、level 0 の答えに `postalCode` を付けて返します。
2. まず市区町村までを読みます。ここでは市区町村のデータを使いません。市区町村までの入力は、これで答えが出ます。
3. 指定した `level` が 3 以上で、市区町村の後ろに文字があれば、その市区町村の町字と番地・号のデータを使って、もう一度読みます。解析は Geolonia の `normalize-japanese-addresses`（MIT、3.1.3 に固定）が行います。Sora は、ライブラリがファイルを読む処理を差し替えて、ABR から作った手元のデータを渡します。ライブラリは「9番9号」「９－９」のような番地・号の表記を 9-9 の形にそろえます。ライブラリは町の一覧をメモリに残し続けるので、配るデータが変わったときと 24 時間ごとに、読み込み直します。
4. `level` が 4 以上で、番地・号に届かず、データの不足でもないときは、言い換えた入力を試し、より深く届いた結果を採ります。言い換えは 3 種類だけです。街区表記（「6街区21号」を「6-21」）、「線」「号」「番」の前の漢数字（「六十七番」を「67番」。「一番町」のような地名は変えません）、「葦」と「芦」の異体字（ABR の綴りの「葦北郡芦北町」に合わせる）です。
5. 住所が読めず（level 0）、先頭の郵便番号か `zipcode` があれば、郵便番号が 1 つの市区町村に決まるときに限り、その都道府県と市区町村を補って、読み直します。先頭の郵便番号が `zipcode` より優先です。日本郵便は、正しい郵便番号があれば市区町村名を省いてよいとしています。
6. ABR で番地・号に届かず、町字までは読めていて読み残しの文字があるときは、国土交通省の街区のデータで街区符号を引きます（`numberSource: "mlit"`。指定した `level` が 4 以上のときだけです）。ABR で届く住所には使いません。ABR の地番に座標が無いときも、同じ本番の街区の点を座標に使います（`pointSource: "mlit"`）。この場合も、番地の照合の根拠は `chiban` のままです。
7. 結果を整えます。
   - `keys`: 都道府県コード、6 桁の全国地方公共団体コード、町字 ID、住居表示の街区符号・住居番号、または地番の番号。
   - `numberSource`: 番地・号を何で照合したかです。`rsdt` は住居表示、`chiban` は地番、`mlit` は国土交通省の街区（街区符号まで。号は未照合）、`null` は整形だけで未照合です。
   - `point`: 代表点の座標と、その細かさ（`point.level`。8 は番地・号、7 は街区、3 は町字）。
   - `postalCodes`: 住所に当たる郵便番号。
   - `dataset`: 使ったデータのうち最も古い更新日（`updatedAt`）と、確認が期限の 2 倍を超えたか（`stale`）。
   - `attribution`: 出典。地番や国土交通省のデータを使った結果には、その出典が加わります。
8. 突き合わせの結果は、`checks` に入ります。郵便番号の突き合わせ（`checks.zipcode`）は、`zipcode` を渡したときと、住所の先頭に郵便番号があるときに行います。座標（`lat`・`lon`）の突き合わせは `checks.coordinates`、名寄せは `checks.compare` に入り、どちらも指定したときだけ行います。
   - **`zipcode`**: 郵便番号が住所に当たるかです。`match`（町域の番号に含まれる）、`partial`（同じ市区町村だが町が違う、または市区町村の既定の番号だけ）、`mismatch`（市区町村が違う、または存在しない）、`unknown`（市区町村まで読めない）。
   - **`lat`・`lon`**: 座標の最寄りの住所を逆引き（[reverse-geocoding.md](reverse-geocoding.md)）して、住所と比べます。住所が書いている階層まで一致すれば `match` です（市区町村までの住所なら、その市区町村の中の座標）。番地・号まで書いた住所は、150m 以内のときだけ `match` で、離れていれば `partial` です。同じ町字でも街区（地番は本番）が違えば `partial` です。市区町村が違えば `mismatch` です。
   - **`compareAddress`**: 都道府県、市区町村、町字、番地・号の順に比べて、最初に違う階層で止めます。結果は `identical`、`same-block`、`same-town`、`same-city`、`same-prefecture`、`different` のどれかです。番地・号をデータで照合できていない住所は、文字列で比べ、一致の深さ（`sameLevel`）を 3 までにします。

## 決められないとき

この処理は、聞き返しません。読めたところまでを返します。

- 住所が読めないとき、または途中までしか読めないときは、エラーにせず `level` を下げて返します。読めなかった残りは `other` に入ります。建物名・部屋番号も、解析せずに `other` に残ります。
- データが待ち時間に間に合わなかったときは、取れている範囲の答えに `incomplete: true` と、足りないデータの ID（`pending`、例: `city:131016`）を付けます。しばらくして同じ要求を送ると、完全になります。取得に失敗したデータは `unavailable` に入ります。
- 答えようがないときは、REST がエラーを返します。
  - 400 `INVALID_INPUT`: 住所が空か長すぎる、`level` が 1 から 8 の整数でない、`zipcode` が 7 桁でない、`lat` と `lon` の片方だけ。
  - 502 `ADDRESS_DATA_PENDING`: 全国マスターが待ち時間に間に合いません。再試行できます。
  - 502 `ADDRESS_DATA_UNAVAILABLE`: データを取得できません。国外 IP の拒否では、再試行できないと返します。
  - 404 `ADDRESS_DISABLED`: `SORA_ADDRESS=off` です。

例です（テストの見本データでの結果の一部です）。

```json
{ "address": "東京都千代田区永田町1-7-1", "zipcode": "100-0014", "compareAddress": "千代田区永田町一丁目7番1号" }
```

```json
{
  "normalized": "東京都千代田区永田町一丁目7-1",
  "level": 8,
  "numberSource": "rsdt",
  "keys": { "prefCode": "13", "lgCode": "131016", "blk": "7", "rsdt": "1" },
  "checks": {
    "zipcode": { "status": "match" },
    "compare": { "relation": "identical", "sameLevel": 8, "differences": [] }
  }
}
```

## 限界

- 座標は、町字・街区・番地の代表点です。土地の形（ポリゴン）ではありません。座標が建物の位置を表すとは限りません。
- 国土交通省の街区で補った結果は、街区符号までの照合です。号は照合しておらず、確認済みの番地として扱えません。
- 建物名と部屋番号は読みません。名寄せでは、番地・号が同じで建物名だけが違うと `same-block` になります。
- 番地・号を ABR で照合できていない住所の名寄せは、文字列の比較です。同じ場所の別の書き方が `identical` にならないことがあります。
- ABR に無い住所は補えません。新しい住所、片仮名の街区符号、大字の無い住所などです。言い換えも 3 種類だけです。
- 文字列の解析は、ライブラリの挙動に従います。日本語で書いた日本の住所を想定しています。
- データは、取得元が更新して、期限（7 日か 30 日）を過ぎて再確認するまで、古いままです。古さは `dataset.updatedAt` と `stale` で分かります。
- 地番を使った結果には、法務省の登記所備付地図データの出典が付きます。地番から所有者などの個人を特定する用途には使えません。
