# 「明日」を日付に直して予定をまとめる

ページの文に「明日発売」と書いてあっても、その「明日」がいつなのかは、記事を書いた日がわからなければ決まりません。古い記事の「明日」を、読む人（や AI）が今日から見た明日と取り違えると、予定を誤ります。Sora は、本文の相対的な日付の表現を、記事の公開日時を基準にした日付に直して注記します。あわせて、複数のページに載っている同じ予定を 1 件にまとめます。どちらも規則で決めます。LLM は使いません。

## 使うツール

- 注記: `scrape`・`scrape_batch`・`crawl_site`・`search_deep` の `annotateTemporal: true`。REST では `POST /scrape`・`/scrape/batch`・`/crawl`・`/search` の同じ引数です。既定は false です。
- 予定のまとめ: `search_deep` の応答の `schedule`（`verbose: true` のときはまとめず、ページごとの `events` のままです）
- 問いの日付の扱い: `search_deep` と `scrape` のハイライト選び（`query` に日付や「明日」があるとき）

## 手元のデータと外への問い合わせ

手元のデータは、コードの中の表だけです。

- 相対的な日付の表現を読む規則（下の表）
- 問いの中の相対日の語 5 語（明後日・明日・今日・昨日・一昨日。`src/retrieval/lexicons/temporal.ts`）

外への問い合わせはありません。日付の計算は、Sora を動かしている環境の時計とタイムゾーンで行います。

## 決め方

### 本文の相対的な表現に日付を注記する（`annotateTemporal`）

1. **基準の日を決める。** ページの公開日時（`publishedTime`）が読めればそれを使います。なければ、実行した日です。
2. **表現を見つけ、基準の日から日付にする。** 対応しているのは次のとおりです。

   | 表現 | 解決 |
   |---|---|
   | 明後日・あさって | +2 日 |
   | 明日・明朝・翌日 | +1 日 |
   | 本日・今日・当日 | 基準の日 |
   | 昨日・前日 | −1 日 |
   | 一昨日・おととい | −2 日 |
   | N 日前・N 日後（N は 1〜365。全角数字も可） | ±N 日 |
   | 今週・来週・再来週・先週 + 曜日（「来週金曜日」「今週の日曜」） | 基準の日の週（月曜はじまり）から数えた、その曜日 |
   | 今月・来月・再来月・先月 | 基準の日と同じ日付を、月だけずらした日。ずらした先の月にその日がなければ、その月の末日（1月31日の「来月」は 2月28日）。確度は `medium`（ほかは `high`） |

   「一昨日」は 2 日前の 1 つとして読み、中の「昨日」を別に 1 日前として拾うことはありません。「当日券」「当日精算」「当日受付」「当日払い」「当日料金」の「当日」は日付ではないので、拾いません（単独の「当日」は基準の日です）。

3. **注記を入れる。** 表現の直後に `[YYYY-MM-DD]` を入れます。同じ表現が本文に何度出ても、すべてに入れます。長い表現から先に処理し、すでに注記があるところには重ねません。リンクと画像の飛び先 `](…)` の中には入れません（リンクの文字と代替テキストには入れます）。
4. **結果を返す。** 本文（`content`）に注記を入れます。ハイライトにも、同じ基準の日で注記します。表現・基準の日・解決した日・曜日・確度の一覧は `temporalAnchors` です。`search_deep` のページには付きます。`scrape` では `verbose: true` のときだけ付き、既定の応答には注記を入れた本文だけが出ます。

例: 公開日時が 2026-09-01 のページに「新作は明日発売です。」とあれば、本文は「新作は明日 [2026-09-02]発売です。」になります。

```json
{ "expression": "明日", "referenceDate": "2026-09-01", "resolvedDate": "2026-09-02", "resolvedDayOfWeek": "水曜日", "confidence": "high" }
```

### 問いの日付の年を想定する

問いに「10月11日」のように年のない日付があると、ハイライトの採点で、その日付を含む文の年を見ます。想定する年は、次のとおりです。

1. 問いに年があれば、その年。
2. なければ、実行した日以降にその日付が来る年。今日と同じ日付は今年です。過ぎていれば来年です。

たとえば 2026-09-30 に調べると、「10月11日」は 2026 年、「9月1日」は 2027 年です。問いの「明日」「今日」なども、実行した日から日付にします。文の年が想定する年と同じなら 1.1 倍、違えば 0.8 倍にします。文に年がなければ変えません（[search-evidence.md](search-evidence.md)）。

Web 検索の言い換えの候補（最初の検索が弱いときや 0 件のときに試す検索語）でも、「明日」などは日本時間の日付（「11/10」と「11月10日」の形）に直します。

### 複数ページの予定をまとめる（`schedule`）

予定は、各ページの構造化データ（JSON-LD の Event など）に書かれたものです。

1. 名前のない予定は捨てます。
2. 各予定に、開始日（日本時間）と、正規化した名前のキーを付けます。名前の正規化は、全角・半角と大文字・小文字をそろえ、空白と記号を取り除くことです。開始日がなければ「日付なし」として扱います。
3. キーが同じ予定は 1 件にします。先に出た値を残し、空の項目（終了日・会場・出演者・説明・URL・開催状況・参加形態・チケット）は、あとから出たもので補います。載っていたページの URL を `sources` に並べます。
4. 並べます。開催中と今後の予定を近い順、日時が読めない予定（元の順）、過去の予定を新しい順です。予定は削除しません。

日付だけの値（`2026-11-20`）は日本時間の 0 時（開始）・23 時 59 分（終了）として、タイムゾーンのない日時は日本時間として読みます。

## 決められないとき

聞き返しやエラーはありません。決められないものは、そのまま残します。

- 対応していない表現は、注記を付けず、元の文のままにします。
- 公開日時がないページは、実行した日を基準にします。この場合、古いページの「明日」は誤った日になりえます。`temporalAnchors` の `referenceDate`（`scrape` は `verbose: true` のとき）で、どの日を基準にしたかを確かめられます。
- 日時が読めない予定は、「日時不明」の位置（今後の予定の後ろ、過去の予定の前）に並べます。

## 限界

- 基準はページの公開日時だけです。更新された日、本文中の別の日付、ページに書かれた「○月○日現在」は使いません。
- 「当日」「翌日」「前日」も同じ規則で直します。「当日券」「当日精算」「当日受付」「当日払い」「当日料金」の「当日」は外していますが、ほかの複合語（「前日比」など）の中の語は、日付として注記することがあります。
- 「今月」「来月」は、同じ日付を月だけずらした日を注記します。月全体を指す語に日付を付けるので、日付そのものとしては読まないでください。
- 同じ種類の表現（たとえば「明日」と「翌日」）が 1 つの文章に別々の意味で出ても、最初に出たものの日付を使い、同じ種類の別の語には付けません。
- 「来週」だけ、「週末」「今夜」「来年」「金曜日」だけ、「10月11日」のような年のない日付は、注記しません。年のない日付の想定は、問いの日付の採点にだけ使います。
- 本文が過去の記事の引用でも、すべて公開日を基準にします。
- 日付の計算は、検索の言い換え（日本時間）を除いて、実行環境のタイムゾーンで行います。公開日時が別のタイムゾーンで書かれていると、基準の日がずれることがあります。
- 予定は、構造化データがあるページだけから集めます。文章に書かれた予定は、`schedule` に入りません。名前が違えば、同じ日・同じ会場でも別の予定のままです（誤って 1 件にまとめて予定を隠すより、重複を残すほうが害が小さいため）。
- 海外の予定でも、日付だけの値は日本時間として扱います。
