# 静的な取得で足りるかを判定する

`scrape` は、まず普通の HTTP 取得（静的な取得）でページを読みます。ほとんどのページはこれで足ります。ただし、JavaScript が本文を組み立てるページ（SPA）や、確認画面だけを返すページ、取得を断るページでは、本文が空かほとんど空になります。ブラウザ（Chromium）で描画すれば読めることがありますが、ブラウザは重く、1 ページあたり約 300MB のメモリが目安です。README の測定では、静的な取得が約 79 ミリ秒、ブラウザでの描画が約 0.8〜1.3 秒です。Sora は、静的な取得の結果を見て、そのまま使うか、ブラウザに切り替えるかを決めます。

## 使うツール

- MCP: `scrape`、`scrape_batch`、`crawl_site`。`search_deep` と `search_web`（`formats` を指定したとき）の本文取得も、同じ処理を通ります。
- REST: `POST /scrape`・`/scrape/stream`・`/scrape/batch`・`/crawl`
- 切り替えの指定: `mode`（`auto`・`fast`・`browser`。既定は `auto`）。REST だけ、`renderJs`（`browser` と同じ）と `fastOnly`（`fast` と同じ）があります。

## 手元のデータと外への問い合わせ

手元のデータは、コードの中の固定の文言と数値だけです。ボット対策の確認画面や JavaScript の要求を示す文言、SPA の作り方を示す目印 14 個（`id="root"`、`__NEXT_DATA__` など）、しきい値（50 字・300 字・45 点・0.5）です。取得して更新するものはありません。

外へは、取得先のサイトへ要求を送ります。静的な取得を 1 回、ブラウザへ切り替えたときはブラウザで 1 回です。ほかのサービスには問い合わせません（下の専用の経路を除きます）。ブラウザは、実行環境に Chromium があるときだけ使えます。

取得結果は 30 分、手元のキャッシュに残します。本文を読めなかった結果と、警告の付いた結果は 1 分です。Cookie や認証ヘッダーを付けた要求の結果は、共有のキャッシュに入れません。

## 決め方

### 最初に経路を分ける

1. `mode: "browser"`（`renderJs`）なら、最初からブラウザで開きます。`mode: "fast"`（`fastOnly`）なら、静的な取得だけで、ブラウザには切り替えません。
2. 一部の URL は、通常の取得に回しません。
   - YouTube の動画（`youtube` モジュールが有効なとき）: 字幕と説明文から本文を作ります（[youtube-transcript-selection.md](youtube-transcript-selection.md)）。ページの HTML・リンク・画面の画像を求めたとき、ブラウザでの描画を指定したときは、通常の取得です。
   - X のアカウント・投稿: ページは読まず、投稿の検索と全文の取得から本文を作ります（[x-search.md](x-search.md)）。作れなければ、通常の取得に戻ります。
   - TikTok の動画: 最初からブラウザで開きます（`fast` を指定したとき、Chromium がないとき、ページそのものを求めたときを除く）。
3. 画像・音声・動画のファイルは、中身を読まず、種類と大きさだけを返します。PDF は PDF として読みます。

### 静的な取得の結果から、ブラウザが要るかを決める（`mode: "auto"`）

1. 静的に取ります。リダイレクトは 5 回まで、時間切れは 15 秒です（`search_deep` では 12 秒）。取った HTML から本文を取り出します（[検索・スクレイプの仕組み](../search-scrape-mechanics.md) の「本文の取り出し」）。
2. 次のどれかに当たれば、ブラウザが要る候補にします。Chromium がなければ、候補にしません。
   - HTTP の状態が 403・429・503。
   - 確認画面（ボット対策）を示すヘッダー、またはページ中の文言がある。
   - 「JavaScript を有効にしてください」「JavaScript is required」のような要求の文言、または「Loading」「読み込み中」だけの本文。
   - 取り出した本文が 50 字未満。
   - SPA の目印があり、本文が 300 字未満。本文が 300 字以上あれば、目印があっても足りるとみなします。
   - 本文の品質の点が 45 点未満（下の「品質の点」）。
3. 候補になっても、問い（`query`）があるときは、静的な本文に答えがあるかを見て、ブラウザへの切り替えを取りやめることがあります。
   - 本文が 50 字未満、または問いがないときは、取りやめません。
   - 静的な本文から、問いに合うハイライトを 5 件選びます。問いから、最大 10 語の要件語を選びます。
   - そのハイライトの中で、要件語の半数以上（0.5 以上）について、その語のある文か、続く 2 文に値（金額・重量・日付・時刻・バージョン・Wi-Fi 規格）が見つかれば、取りやめます。
4. 切り替えると決めたら、ブラウザで開いて描画します。描画のあとで本文が出ているかを、同じ種類の判定で確かめます。本文が 50 字未満、JavaScript の要求の文言、確認画面の文言、またはカレンダーの枠だけのときは、同じページで最大 2 秒ほど待って、確かめ直します。
5. ブラウザが失敗したとき（時間切れなど）は、静的に取れた本文が 50 字以上あれば（`screenshot` を求めたときは、短くても）、静的な結果を返します。なければエラーです。
6. HTTP の状態が 400 以上のページは、静的でもブラウザでも、本文として扱いません（`contentStatus: "unavailable"`）。ブロックやエラーの画面を、答えの根拠にしないためです。

`formats` に `screenshot` があるときは、`auto` でも、静的に取ったあとでブラウザで画像を撮ります。本文と HTTP の状態は静的な取得のままで、ブラウザからは画像だけを使います。

### 品質の点

静的な結果の品質を、0〜100 の点にします。50 点を基準に、足し引きします。

| 状態 | 点 |
|---|---|
| 確認画面、または JavaScript の要求の画面と判定 | 10 点にして終わり |
| 本文 50 字未満 | −40 |
| 本文 50〜199 字 | −15 |
| 本文 501〜2,000 字 | +15 |
| 本文 2,000 字超 | +25 |
| 見出しがある | +15 |
| 構造化データ（JSON-LD）がある | +15 |
| 題名と説明文がそろっている | +10 |
| リンク（URL を含む）が本文の 6 割を超える（本文 100 字超） | −20 |

本文が 200〜500 字なら加減しません。本文が説明文だけ、または何もないページは、20 点以下にします。そのため、本文が空のページは、45 点未満になって切り替えの候補に入ります。`verbose: true` のときは、`quality` と、その理由の `qualityReasons`、ブラウザを使ったかを示す `renderedWithBrowser` が付きます。

## 決められないとき

聞き返しやエラーにはせず、読めたかどうかを `contentStatus` で伝えます。

| `contentStatus` | 意味 |
|---|---|
| `body` | 本文がある |
| `structured_data` | 本文はないが、構造化データの説明がある |
| `metadata_only` | 説明文や予定だけで、本文がない |
| `unavailable` | 読めなかった（エラーの画面、確認画面、画像などのファイル） |

例: 取得が 403 を返し、ブラウザにも切り替えられない（`mode: "fast"` を指定した）とき。

```json
{
  "url": "https://shop.example.test/item/1",
  "contentStatus": "unavailable",
  "content": "HTTP 403 が返ったため、本文として扱いません。\n\n…"
}
```

`unavailable` の結果は、`search_deep` では読めたページの後ろに回し、根拠にも数えません。

## 限界

- 判定は、固定の文言・目印・しきい値です。網羅ではありません。知らない作り方の SPA や、文言の違う確認画面は、見逃すことがあります。
- 本文が 300 字以上ある殻のようなページ（ナビゲーションの文だけが長いなど）は、SPA の目印があっても、足りるとみなされます。
- 答えがあるかの確認（取りやめ）は、値を探す問いのためのものです。人名や理由のように値のない答えは、静的な本文にあっても取りやめになりません。そのときは、目印があればブラウザに切り替わります。
- ブラウザでも確認画面のままになることがあります。HTTP の状態が 200 だと、その画面の文が本文として返ります。`verbose: true` の `quality` が低く、`qualityReasons` に `bot_challenge_detected` が出るので、見分けられます。
- 品質の点は、本文の量と構造を見るだけです。内容が正しいかは見ません。
- `docs/evaluations` にあるのは、本文の取り出し（`main-content`）と、描画の待ち方（`browser-readiness-timetree-20261007.md`）の評価です。この判定そのものの精度を測った記録はありません。
- 切り替えると、時間とメモリを使います。使いたくないときは、`mode: "fast"` を指定してください。
