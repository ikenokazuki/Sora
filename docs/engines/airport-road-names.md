# 空港・都道府県・道路の名前を解決する

「羽田」「HND」「ＨＮＤ」「羽田空港国際線ターミナル」は同じ空港を指し、「東名」「東名高速道路」は同じ道路を指します。運航情報や道路交通情報の元のサイトは、空港や都道府県を内部の番号で引くので、入力の名前を番号に直す必要があります。

名前を含んでいるかどうかだけで当てると、「東京駅」を羽田にしたり、「羽田と成田」のどちらかに黙って決めたりします。解決できない都道府県を東京にしてしまうこともあります。Sora は、決められない名前を別の空港や県に黙って替えず、エラーにします。

## 使うツール

- MCP `get_flight_status`（モジュール `life`）。REST は `POST /traffic/flight`、`GET /traffic/flight`、`GET /traffic/flight/:airport`。
- MCP `search_road_traffic`（モジュール `disaster`）。REST は `POST /traffic/road`、`GET /traffic/road`、`GET /traffic/road/:pref`。
- どちらも名前の解決をしてから、元のサイトのページを読みます。

## 手元のデータと外への問い合わせ

- 手元にあるのは、`src/services/traffic.ts` に手書きした 3 つの表です。空港は 35 の書き方で 5 空港（羽田・成田・伊丹・関西・中部）、都道府県は 149 の書き方で 47 都道府県、道路は 33 の書き方で 15 の高速道路（東名・中央道・関越道・東北道・常磐道・圏央道・アクアライン・上信越道・北陸道・名神・東名阪・山陽道・中国道・九州道・道央道）です。更新の仕組みはなく、書き方が足りなければコードを直します。
- 名前を解決する段では、外に何も送りません。
- 解決したあと、Yahoo! JAPAN の運航情報・道路交通情報のページを 1 枚読みます。道路の応答の `source` は `jartic`、運航情報は `yahoo-transit` です。
- 結果は 3 分キャッシュします。`noCache` で飛ばせます。

## 決め方

空港（`resolveAirport`）の順序です。

1. 入力を NFKC（全角の英数字・半角のカナなどを標準の形にする正規化）で整え、小文字にします。省略・空白だけなら羽田です。
2. 表の書き方と全体が同じなら、その空港です。
3. 同じでなければ、入力が表の書き方を含んでいるかを見ます。日本語の書き方は含んでいればよく、英字の書き方は単語として含まれているときだけです。「mango」の中の「ngo」や「hndx」は拾いません。入力の一部が書き方に含まれるだけの断片（「羽」「o」）も受けません。
4. 当たった空港がちょうど 1 つなら、その空港です。「羽田空港国際線ターミナル」や「Tokyo Haneda」がこれです。
5. 2 つ以上なら、「空港を 1 つだけ指定してください」のエラーです。0 なら、「対応は羽田・成田・伊丹・関西・中部の 5 空港です」のエラーです。
6. 「東京」「tokyo」は、入力がこれだけのときに限って羽田にします。「tokyo narita」は成田、「東京駅」はエラーです。

都道府県（`resolvePrefecture`）の順序です。

1. 数字だけの入力は、1〜47 ならそのコードの都道府県です。範囲の外はエラーで、「13abc」を 13 とは読みません。
2. それ以外は、小文字にして表を引きます。「愛知」「愛知県」「aichi」は同じで、「名古屋」「横浜」「神戸」など 9 つの都市名も、その県に引けます。

道路は、空白を除いた入力で表を引きます（`resolveRoadCode`。完全に同じ書き方だけです）。そのあと、どのページを読むかを決めます。

1. 道路が表にあり、都道府県の指定がなければ、その道路のページを読みます。上りと下りの区間ごとの状況が取れます。
2. それ以外は、都道府県のページを読みます。都道府県も道路も省くと東京都です。
3. `road` を指定したときは、そのページの道路名を絞ります。道路名が指定の語を含むか、表で同じ道路になる名前（「中央自動車道」と「中央道」）なら残します。
4. 規制・事故の項目があれば `hasIssues` を立て、件数を要約に書きます。「規制情報はありません」「順調」だけなら順調と書きます。

便の取得（空港が決まったあと）は、`type`（既定は出発）と `category`（既定は国内線）で読むページを選びます。ページに埋め込まれたデータを読み、読めなければページの表を読みます。`flightNumber`（大文字・空白なしで含む）と `keyword`（航空会社・行き先・案内文・状態に含む）で絞ります。

## 決められないとき

- 空港が決まらないとき、都道府県が解決できないときは、入力の誤りとして返します（REST は 400 `INVALID_INPUT`、MCP はエラー応答）。元のサイトには問い合わせません。
  - 例: 空港に「福岡」を渡すと、「空港「福岡」には対応していません。対応は羽田・成田・伊丹・関西・中部の 5 空港です」と返します。
  - 例: `pref` に「ほげ」を渡すと、都道府県が見つからないというエラーです。東京都にはしません。`pref` を省くか空にしたときだけ東京都です。
- 道路を絞って 0 件のとき、またはページから 1 件も読めなかったときは、「この道路の情報は見つかりませんでした。」と返します。「順調」とは書きません。
- 空港の `get_flight_status` で、ページから便が 1 件も読めなかったときは、「便の情報を読み取れませんでした」と書き、運航状況は言いません。ページの一覧が空だった場合と、ページの作りが変わって読めなかった場合は区別しないで、1 つの文で両方を言います。この結果は、取り直せるようにキャッシュしません。`flightNumber`・`keyword` で絞って 0 件になったときは「条件に合う便はありません」と書きます。どちらも `count` は 0 で、「順調」とは書きません。
- 元のサイトが HTTP エラーを返したときは、そのエラーを返します（REST は 500 `TRAFFIC_ERROR`）。

## 限界

- 表は手書きなので、書き方の網羅は保証しません。空港は 5 つだけで、福岡・那覇などは扱いません。
- 都道府県を省き、表に無い道路名（例: 首都高）だけを渡すと、東京都のページだけを探します。応答の `pref` は東京都になり、他の都道府県の道路は見つかりません。道路の応答の `pref` を確かめてください。
- 要約の件数に数えるのは「欠航」と「遅れ」で、「見合わせ」は `hasDelaysOrCancellations` の判定には入りますが、件数には入りません。
- 道路の要約の「N 件の規制・事故」は、順調と書かれた区間も含めた行の数のことがあります。`items` の `status` で確かめてください。
- 運航・道路の状況は、元のサイトが表示した時点のものです。`updatedAt` を見てください。
- 日本の天気の地名を引き当てる仕組みは別です。[日本の地名を気象庁の予報区に引き当てる](weather-place-names.md)を見てください。
