# 地名や住所を座標にする順序

標高の取得や周辺施設の検索は、座標（緯度経度）が要ります。利用者は、「原宿」「東京都千代田区永田町1-7-1」「100-0014」「富士山頂」のように、種類の違う文字列で場所を渡します。Sora は、住所と郵便番号は手元の公式データで、地名・駅名・施設名は外部の地図データで座標にします。どれを先に使うかと、結果をどこまで信用してよいかを決めるのが、この処理です。特に、番地が入力にあるのに番地の点が得られないときは、町の代表点を番地の座標として返しません。

用語です。

- **自前のデータ**: Sora が取得して手元に持つ、デジタル庁の住所データ（ABR）と日本郵便の郵便番号データです（[address-normalization.md](address-normalization.md)、[postal-code.md](postal-code.md)）。
- **`needsVerification`**: 座標が意図した場所かの確認を、呼び出し側に求める印です。Sora は聞き返さず、先頭の候補を返して、この印を付けます。

## 使うツール

- MCP: `get_place_info`（`address` を座標にして、`include` で選んだ情報を返す。既定は標高。座標解決の欄は `location`、標高の欄は `elevation` の節）、`search_poi`（`center` の地名を座標にして周辺の施設を返す。`withAddress` で施設の住所も調べる）
- REST: `POST /geo/elevation`、`GET /geo/elevation`、`POST /geo/poi`、`GET /geo/poi`

`lat` と `lon` を直接渡したときは、座標の解決をしません。

## 手元のデータと外への問い合わせ

自前のデータは、取得済みの市区町村の分だけ使います。ここでは取得を待ちません。データが無ければ、`SORA_ADDRESS_MODE` が `lazy`（既定）のときは何も頼まず、`eager` のときは裏で取得を始めて、その回は次の経路に進みます。`SORA_ADDRESS_MODE=off` のときは、自前の経路を使いません。

自前で決まらないときは、外部のサービスに問い合わせます。入力した地名や住所の文字列が、そのまま外に送られます。

- 国土地理院の住所検索（番地まである住所は、こちらを先に引く。地名・駅名・施設名は Nominatim に該当が無いときだけ）
- OpenStreetMap の Nominatim（日本に限って検索。上位 3 件を見る。地名・駅名・施設名は、こちらを先に引く）

座標が決まったあとの処理にも、外への問い合わせがあります。標高は国土地理院の標高 API に座標を送り、周辺施設は OpenPOI API に座標と半径を送ります。

外部の結果は、24 時間キャッシュします（メモリと、Sora の SQLite のデータベースに保存するので、再起動後も残ります）。自前のデータで決めた結果は、キャッシュしません。Nominatim の利用規約（1 秒に 1 リクエスト）を守るため、同じ Sora のプロセスでは、Nominatim への実際の問い合わせの開始を 1.1 秒以上空けます（MCP と REST、標高と周辺施設で共有。国土地理院への問い合わせは待たせません）。同じ地名の同時の要求は 1 回にまとめます。未キャッシュの地名が続くと、順番に待ちます。`noCache: true` でも、この間隔は守ります。

## 決め方

1. 入力の前後の空白を取ります。空ならエラーです。
2. 自前のデータで決められるか調べます。
   - 郵便番号だけの入力（〒、ハイフン、全角を許す）は、郵便番号の候補のうち、座標のある最初のものを使います。番号が複数の町にまたがるとき、または座標が町の代表点でなく市区町村の代表点のときは、`needsVerification: true` にします。
   - それ以外は、住所として正規化します。町字（level 3）以上で、座標があるときだけ使います。市区町村までしか読めない入力は、地名として次の経路に任せます。
   - 番地・号が入力にある（level 8、または読み残しが数字で始まる）のに、座標の細かさが番地・号（level 8）に届かないときは、使いません。町字や街区の代表点を、番地の座標として返さないためです。地番に位置参照が無い住所も同じです。
   - 入力が不正、データが足りない、取得に失敗した、のどれでも、「自前では決まらない」として次に進みます。
3. キャッシュを調べます。同じ地名の要求が実行中なら、その結果を待ちます。
4. 外部の経路の順は、入力で変わります。
   - 番地まである住所（「1-5-1」のように数字がハイフンでつながる、または数字に「丁目」「番」が付く。「国道246号」は含めません）は、国土地理院の住所検索を先に引きます。先頭の候補を採り、候補が 2 件以上あるときは、`needsVerification: true` にします。該当が無いとき、または国土地理院が HTTP エラーなどで使えないときは、Nominatim に進みます。
   - それ以外（地名・駅名・施設名）は、Nominatim を先に引きます。先頭の候補を採り、上位 3 件が複数の都道府県にまたがるときは、`needsVerification: true` にします。Nominatim が「該当なし」と答えたときだけ、国土地理院に進みます（候補の扱いは同じです）。
5. どちらにも無ければ、エラーです。
6. 座標が決まったら、用途に進みます。標高は、座標から国土地理院の標高を取ります。周辺施設は、座標と半径で施設を探します。
7. `search_poi` で `withAddress` を指定したときは、施設ごとに、住所を正規化し、郵便番号を付け、施設の座標と突き合わせます（`addressInfo`）。データの取得を待つ時間は、全施設で合わせて 20 秒（既定）までです。

応答には、取得元（`geocodingSource`、周辺施設では `centerResolved.source`）として、`abr`（自前のデータ）、`nominatim`、`gsi`（国土地理院）のどれかが入ります。出典の表示（`geocodingAttribution`、`centerResolved.attribution`）も付きます。結果を表示するときは、併記してください。

入力による経路の違いです。

| 入力 | 経路 |
|---|---|
| 東京都千代田区永田町1-7-1 | 自前のデータ（番地・号の点があるとき）。無ければ国土地理院、それでも無ければ Nominatim |
| 100-0014 | 自前のデータ（郵便番号の候補の点） |
| 原宿、渋谷駅、富士山頂 | Nominatim。該当が無ければ国土地理院 |

## 決められないとき

- 候補が複数あるときは、先頭を返して `needsVerification: true` にします。呼び出し側は、`matchedTitle`（標高。MCP の `get_place_info` では `location.matchedTitle`）か `centerResolved.address`（周辺施設）を見て、意図した場所かを確かめます。違うときは、地域名を足して、もう一度呼びます。
- 座標が決まらないときは、エラーです。標高は、REST（`/geo/elevation`）で 500（`GEO_ERROR`）、MCP の `get_place_info` でエラーの応答です。`search_poi` は、`POI center geocoding failed` で始まるエラーです。広域の検索には切り替えません。
- 地名・駅名・施設名で Nominatim が HTTP エラーを返したときは、国土地理院に切り替えず、エラーにします。国土地理院は部分一致で別の地名（例: 「渋谷駅」に福島県の「渋谷」）を返すので、国土地理院に回るのは、Nominatim が「該当なし」と答えたときだけです。番地まである住所で国土地理院が使えないときは、Nominatim で探します。
- 標高が取れなかったときは、`elevationMeters` が `null` で、`formatted` が「測定不能」になります（MCP の `get_place_info` では `elevation` の節）。
- `withAddress` で、住所データが待ち時間に間に合わなかった施設には、`addressIncomplete: true` が付きます。住所を解釈できない施設には、`addressInfo` が付かず、この印も付きません。時間切れと解釈できないことは、この印で区別します。

## 限界

- Nominatim は OpenStreetMap のデータです。番地まで書いた住所には弱いので、番地まである住所は国土地理院を先に引きます。国土地理院は施設名や駅名が当たらないので、地名・駅名・施設名では補いにだけ使います。OpenStreetMap のデータには出典の表示が必要です。
- 先頭の候補を採るだけです。同じ名前の別の場所が選ばれることがあります。`needsVerification` が立つのは、上位 3 件が複数の都道府県にまたがるとき、国土地理院で候補が複数のとき、郵便番号が複数の町にまたがるとき、郵便番号の座標が町でなく市区町村の代表点のときだけです。同じ都道府県の中にある同名の地名では、立ちません。
- 自前のデータは、取得済みの市区町村の分だけです。住所のツール（`lookup_address` など）で一度使った市区町村が対象です。座標の解決は、自前のデータの取得を待たないので、初めて使う市区町村は外部の経路になります。同じ入力でも、時期によって取得元と座標が変わることがあります。
- 自前のデータの座標は、町や番地の代表点です。建物の位置とは限りません。
- 地名・駅名・施設名は、自前のデータでは決められません。外部のサービスが使えないときは、決められません。
- 外部の経路には、入力した地名や住所が送られます。
- 1.1 秒の間隔は、Nominatim への問い合わせにかける、1 つの Sora のプロセスの中の制限です。複数のプロセスの間では調整しません。
- 標高が 0 で、精度が「海水面・データ外」のときは、実際の標高が 0m とは限りません。国土地理院のデータが無い場所も、0 として返します。
