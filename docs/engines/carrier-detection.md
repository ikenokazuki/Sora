# 追跡番号から配送会社を絞り込む

追跡番号の形だけでは、配送会社が決まらないことがあります。たとえば 12 桁の数字は、ヤマト運輸・佐川急便・日本郵便・福山通運・FedEx のどれの形にも当たります。いちばん早く返事をした会社を採ると、別の会社の「保守中」や「該当なし」の画面を答えにしてしまいます。

Sora は、番号の形で会社に順位を付け、上位の少数にだけ問い合わせます。そして「その番号の荷物が実際にある」という証拠が返った会社だけを採ります。証拠のある会社が見つからなければ、会社を決めません。

## 使うツール

- MCP: `track_package`（モジュール `life`。遅延モードでは `search_tools` で有効化します）。引数は `trackingNumber`、`carrier`、`preferredCarriers`、`noCache` です。
- REST: `POST /tracking`、`GET /tracking/:number`（自動判別）、`GET /tracking/:carrier/:number`（会社を指定）。
- `carrier` に会社を指定すると自動判別は行わず、その会社だけに問い合わせます。省略するか `auto` にすると、このページの手順で決めます。
- `GET /t/:carrier/:number` は、結果を人が読める形で表示するページです。環境変数で有効にしたときだけ使え、判別には関わりません。

## 手元のデータと外への問い合わせ

- 手元にあるのは、8 社（ヤマト運輸・佐川急便・日本郵便・西濃運輸・福山通運・UPS・FedEx・DHL Express）の番号の形の規則です。各社のコードに手書きしてあり、表やデータベースは持ちません。国際郵便の番号（UPU S10）の検査数字を計算する処理も手元にあります。
- 形で順位を付ける段では、外に何も送りません。
- 外に出るのは、順位の上位に問い合わせる段だけです。各社の公開の追跡ページに番号を送ります。UPS・FedEx・DHL は、公式 API の資格情報を設定してあれば API を先に使います。なければブラウザで公式ページを開いて読み、それも読めなければ公式ページの URL を案内するだけです。
- 番号を検索サイトなどに送ることはありません。
- 結果はメモリと SQLite にキャッシュします。配達完了は 24 時間、それ以外は 5 分で、`error` は保存しません。`noCache` で飛ばせます。

## 決め方

1. 番号をそろえます。全角の英数字を半角にし、空白・ハイフン・アンダースコア・ダッシュ類を消し、大文字にします。空になれば「追跡番号を入力してください」のエラーです。
2. 8 社が、通信なしで番号の形を点数にします。点数は順位を付けるためのもので、確率ではありません。

   | 会社 | 番号の形と点数 |
   |---|---|
   | ヤマト運輸 | 12 桁 75（strong）、11 桁 65（weak） |
   | 佐川急便 | 12 桁 75、10 桁 70（どちらも strong） |
   | 日本郵便 | UPU S10（英字 2 + 数字 9 + 英字 2）で検査数字が合えば、発行国が JP なら 95、それ以外は 85。検査数字が合わなければ 50（weak）。国内の数字は 13 桁 85、11 桁 75、12 桁 70 |
   | 西濃運輸 | 10 桁 75 |
   | 福山通運 | 11 桁 70（strong）、12 桁 65（weak） |
   | UPS | `1Z` + 英数字 16 文字は 100（exclusive）。`T` + 数字 10 桁、または 9〜12 桁の数字は 50（weak） |
   | FedEx | 数字だけで 12 桁 60、15・20・22・34 桁 85 |
   | DHL Express | 数字だけで 10 桁 60、11 桁 55 |

   `preferredCarriers` に挙げた会社は +15 点です（FedEx の 12 桁と DHL は +20 点）。
3. 点数の高い順に並べます。同点なら strong が先で、それも同じなら上の表の順です。
4. `exclusive` が出たら、他の会社は見ず、その会社 1 社に問い合わせて終わります。`exclusive` にするのは UPS の `1Z` 形式だけです。数字の桁が他社と重なる形は、`exclusive` にしません。
5. それ以外は、上位 4 社までを 2 社ずつの「波」で並行して問い合わせます。1 波目で証拠のある会社が出たら、2 波目は行いません。
6. 各社の結果を、次の規則で `strong`・`weak`・`none` に分けます。
   - 返ってきた番号が、尋ねた番号と違えば `none`。
   - 状態が `not_found` か `error` なら `none`。
   - 履歴か詳細（発送元・届け先・配達日・サービス種別のどれか）があり、状態が `delivered`・`in_transit`・`returned` なら `strong`。
   - 状態が `registered` で履歴があれば `strong`、履歴がなければ `weak`。
   - 状態が `unknown`（公式ページの URL だけを返した結果など）は `none`。
   - 佐川急便だけは、履歴があるのに状態の語を分類できなかった結果（`unknown`）も、番号が合っていれば `strong` にします。
7. 採る会社を決めます。
   - `strong` が 1 社なら、その会社です（`resolvedCarrier.method` は `network_verified`）。
   - `strong` が 2 社以上なら、どれも採らず競合として返します（`ambiguous_conflict`）。
   - `strong` が 0 社で、問い合わせた会社のどれかが失敗していたら（例外・時間切れ、または会社の側が `error` を返した）、`status: "error"` で返します。荷物が無いとは言えないからです（`unverified_fallback`）。
   - `strong` が 0 社で、失敗した会社がなければ、見つからなかったとして返します（`unverified_fallback`）。

例（番号は架空です）。入力が `1234-5678-9012` なら、正規化して `123456789012` になります。点数は、ヤマト 75、佐川 75、日本郵便 70、福山 65、FedEx 60、UPS 50 です。問い合わせるのは上位 4 社で、1 波目がヤマトと佐川、どちらも `strong` でなければ 2 波目が日本郵便と福山です。FedEx と UPS は問い合わせません。

## 決められないとき

- どの会社の形にも当たらないとき（候補が 0 社）は、`carrier: "unknown"`、`status: "not_found"`、「該当する配送会社を特定できませんでした」を返します。`trackingUrl` は番号を検索サイトで調べる URL で、Sora は開きません。
- 複数の会社で証拠が出たときは、`status: "unknown"` で「複数の配送会社（…）で該当する荷物情報が確認されました。配送会社を明示して照会してください。」と返します。呼び出し側は `carrier` を指定してもう一度尋ねます。
- 証拠のある会社が無く、問い合わせた会社のどれかが失敗したときは、`status: "error"` で、失敗した会社の名前を文に入れて返します。`error` に会社ごとの理由が入り、`trackingUrl` は最初に失敗した会社の公式ページです。ほかの会社が「該当なし」と答えていても、同じです。`error` はキャッシュしないので、尋ね直せば照会し直します。他の会社が証拠を返していれば、失敗した会社があっても、その会社が採られます。
- 証拠のある会社が無く、問い合わせた会社がすべて「該当なし」と答えたときだけ、`status: "not_found"` で、問い合わせた会社の名前を文に入れて返します。`trackingUrl` は先頭候補の公式ページです。`resolvedCarrier.confidence` は `weak` です。
- 公式ページの URL だけを返した結果は `none` なので、自動判別では勝てません。資格情報がなく、ブラウザでも読めない UPS・FedEx・DHL がこれに当たります。
- 返却の `verification`（`level` と `reasons`）で、証拠の強さを確かめられます。

## 限界

- 番号の形の規則は、各社の番号の形から書いた手書きの経験則です。各社が公式に定めた仕様ではありません。
- 10〜12 桁の国内の番号は、形だけでは決まりません。通信で確かめて初めて決まります。
- 問い合わせるのは上位 4 社までです。たとえば 12 桁の番号では、ヒントがなければ FedEx と UPS は問い合わせません。その会社の荷物だと分かっているなら、`carrier` で指定するか `preferredCarriers` に挙げてください。
- 公式ページの URL だけを返した会社（`unknown`。資格情報がなく、ブラウザでも読めない UPS・FedEx・DHL）は、失敗には数えません。ほかの会社がすべて「該当なし」なら `not_found` になります。その会社が問い合わせに入っていたかは、文の「照会対象」で確かめてください。
- 自動判別の `error` は、失敗した会社の名前と理由を返すだけで、その会社に荷物があるかどうかは分かりません。会社を指定して尋ね直してください。
- 外国発行の S10 番号も、日本郵便の国際追跡で引きます。外国の郵便会社そのものの追跡は持ちません。
- 各社のページの作りが変わると読めなくなります（佐川急便は 2026 年 10 月に問い合わせサービスが変わりました）。
- 配達状況の正しさは、各社のページに従います。
