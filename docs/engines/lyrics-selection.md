# 歌詞の取得元を順にたどって同じ曲を選ぶ

歌手名と曲名から、歌詞を取得するエンジンです。**歌詞取得は任意のモジュール `lyrics` で、`ENABLED_MODULES` に `lyrics` を名前で挙げたときだけ有効になります。`all` には含まれません。** 歌詞は著作物なので、個人利用の範囲で使う自己責任の機能です。このページにも歌詞の本文は載せません。

歌詞のデータベースの検索結果は、同じ曲の重複登録、表記の違い、同名の別の曲を含みます。先頭の 1 件をそのまま返すと、別の曲や別の歌手の歌詞を返してしまいます。Sora は、取得元を決まった順に引き、曲名と歌手が合う記録だけを選び、重複は多数決で 1 つに決めます。

## 使うツール

- MCP `get_lyrics`（モジュール `lyrics`。遅延ツールなので `search_tools` で有効化します）。引数は `title`（必須）、`artist`、`noCache` です。
- REST `POST /lyrics`。モジュールが無効なら 404 `MODULE_DISABLED` で、OpenAPI の仕様書にも現れません。
- `artist` は省けますが、LRCLIB に無い曲を AWA や LinkCore で探すには必要です。

## 手元のデータと外への問い合わせ

- 手元に歌詞のデータはありません。持っているのは、名前を比べる規則だけです。起動時の処理・常駐タイマー・事前取得はありません。
- 外に出るのは、呼ばれたときの取得元 3 つです。
  1. LRCLIB（利用者が投稿した歌詞のデータベース）。API キーは要りません。8 秒で時間切れとし、429・502・503・504 のときだけ 1 回待って再試行します（`Retry-After` を守り、待つのは最大 5 秒と少しの揺らぎです）。
  2. AWA の公開の曲ページ。Web 検索で入口を 1 件見つけ、ページを 1〜2 枚読みます。
  3. TuneCore Japan の LinkCore。Web 検索で入口を見つけ、リリースのページをたどります。
- AWA と LinkCore の入口には、Yahoo! JAPAN の Web 検索を使います。
- 結果は、歌詞を含めて 30 分キャッシュします（Sora のキャッシュはメモリと SQLite）。LinkCore のリリースの情報（題名・URL・リンクだけで、歌詞は含みません）は 24 時間です。取得元が使えなかった結果（`search-unavailable`）は、取り直せるように保存しません。

## 決め方

1. 名前をそろえます（`normalizeName`）。NFKC で整え、小文字にし、空白と記号をすべて除きます。比べるときは、いつもこの形です（キャッシュの鍵も同じです）。記号だけの名前（「♪」「!!!」）は、除くと空になってしまうので、そのときだけ、記号と空白を除かずに、全角半角と大小文字だけそろえた名前（前後の空白は除く）を使います（「！！！」と「!!!」は同じです）。空の名前は、何にも一致しません。
2. LRCLIB を引きます。`artist` があれば曲名と歌手名で検索し、0 件のときだけ「歌手 曲名」の自由検索を足します。`artist` が無ければ、曲名だけで検索します。失敗したら（429・502・503・504 は 1 回だけ待って再試行し、それでも失敗したら）、LRCLIB は使えなかったことにして次へ進みます。
3. LRCLIB の結果から、記録を 1 件選びます（`pickLrclibRecord`）。
   - 歌詞の本文がある記録だけを使います。インストゥルメンタルと本文が空のものは除きます。
   - 曲名が完全に一致する記録を探し、無ければ、曲名が入力で始まる記録を探します。
   - `artist` があれば、歌手が一致するものだけに絞ります。一致は、正規化した 2 つの名前のどちらかがもう一方を含めば成り立ちます。ただし、短い方の名前が 3 文字以下のときは、全体が同じときだけです（「ai」は「mai」に一致しません）。
   - 同じ曲の重複登録は、空白を除いて同じ本文ごとにまとめ、いちばん多く登録された本文を採ります。同数なら長い方です。
   - 選ばなかった曲は、別の候補として最大 5 件まで返します。
4. 見つからず、`artist` も無ければ、ここで終わりです。`artist` があれば、AWA、LinkCore の順に進みます。LRCLIB で見つかれば、AWA と LinkCore は引きません。順番は、手間の少ない順に決めてあります。
5. AWA。サイトを限った Web 検索で、その歌手の曲ページを探します。検索語は「歌手 曲名」で、入口が見つからなければ「歌手」だけで探し直します。結果の題名が「“曲名” by 歌手 - トラック・歌詞情報」の形で、歌手が合うものだけを入口にします。曲名が完全に一致する入口があればそのページを読みます。無ければ、入口のページが載せる「同じ歌手の他の曲」の一覧から、曲名が一致するものを探して読みます。ページの歌手が合わなければ採りません。
6. LinkCore。サイトを限った Web 検索で、その歌手のリリースのページを探します。入口のページから、同じ歌手の他のリリースへのリンクを幅優先でたどります（最大 30 ページ、20 秒）。歌手が合い、曲名が完全に一致する最初のトラックで止め、歌詞のページがあれば読みます。
7. 結果を返します。取得できたら、`source`（`lrclib`・`awa`・`tunecore`）と人が開ける `sourceUrl` を付けます。

## 決められないとき

見つからなくても HTTP 200 で `found: false` と `reason` を返します。`candidates` には、LRCLIB の別の曲と、AWA・LinkCore で分かった同じ歌手の曲名を、重複を除いて最大 10 件入れます。表記を直して再実行するための手がかりです。

| `reason` | 意味 |
|---|---|
| `no-match` | どの取得元にも、一致する曲が無い |
| `no-lyrics-registered` | AWA か LinkCore で曲は特定できたが、歌詞が登録されていない。`track` に曲を入れる |
| `search-unavailable` | 取得元が使えず、判断できない。取り直せるようキャッシュしない |

例（名前は架空です）。

```
入力: {"title": "Sample Song", "artist": "Acme Band"}
答え: {"found": false, "reason": "no-match",
       "candidates": [{"title": "Another Song", "artist": "Acme Band"}],
       "notice": "歌詞は著作物です。個人利用の範囲で使い、再配布・公開はしないでください。…"}
```

`title` が空なら入力の誤りで、REST は 400 です。想定外の失敗は REST が 502 `LYRICS_UPSTREAM_ERROR`（`retryable: true`）、MCP がエラー応答です。

## 限界

- 同じ曲の重複は多数決だけで決めます。間違った登録が多数派の曲では、間違った本文を採ります。
- 曲名が完全に一致する記録が無いときは、曲名が入力で始まる別の曲を選ぶことがあります。記号だけの曲名は、全角半角と大小文字をそろえた名前が同じ記録にだけ当たります。
- 歌手の一致は、4 文字以上の名前では「含む」で決めるので、「Acme Band」は「Acme Band feat. ○○」に一致します。3 文字以下の名前は全体が同じときだけなので、「Ai」を探しても「Ai feat. ○○」と載っている記録には一致しません（「ai」が「mai」に当たる誤りを避けるための選択です）。
- LRCLIB は利用者の投稿で、歌詞の正しさは保証されません。LRCLIB を先に引くので、AWA により正しい本文があっても、LRCLIB で見つかればそちらを返します。
- AWA と LinkCore は、公開ページの作りに頼ります。サイトが変えれば取れなくなります。AWA の利用規約は、私的利用の範囲を超える複製・公衆送信を禁じています。
- LinkCore で歌詞が出るのは、権利者が TuneCore に登録した曲だけです。著作権管理団体の管理曲は出ません。曲名が合った最初のトラックで止めるので、別のリリースに歌詞付きの同名曲があっても探しません。30 ページ・20 秒の上限で、たどりきれないこともあります。
- Web 検索が使えないときは、AWA と LinkCore の両方を引けません。
- 歌詞は著作物です。再配布・公開は利用者の責任で避けてください。

音から曲を特定する機能は別のモジュールです。[音から曲を特定して外れを見分ける](song-recognition.md)を見てください。
