# 郵便番号と住所を引き合わせる

郵便番号から住所の候補を、住所から郵便番号を引く処理です。日本郵便の郵便番号データは「町域」の文字列です。デジタル庁の住所データ（ABR）の町字とは、名前の書き方も区切り方も違います。1 つの郵便番号が複数の町にまたがり、1 つの町が複数の番号に分かれ、番号の割り当ては「（１〜１９丁目）」のような括弧の注記で書かれています。文字列を探すだけでは、番号から町の座標も、住所から正しい番号も得られません。Sora は、日本郵便の行を ABR の町字に結びつけて、両方向の引き合わせをします。

用語です。

- **町域**: 日本郵便のデータにある町の名前です。括弧の注記（丁目や番地の範囲など）が付くことがあります。
- **町字**: ABR の町の単位です（[address-normalization.md](address-normalization.md) を参照）。
- **事業所の個別郵便番号**: 大口の事業所や私書箱に割り当てられた番号です。一般の番号とは別のデータにあります。

## 使うツール

- MCP: `lookup_address` に `zipcode` だけを指定する（応答の `mode` は `postal`）。住所から郵便番号は、`address` を指定した[住所の正規化](address-normalization.md)の応答の `postalCodes` です（下の「住所から郵便番号（逆引き）」と同じ処理で、同じ値）。
- REST: `POST /geo/postal-code`、`GET /geo/postal-code`

REST の引数は `zipcode`（郵便番号）と `address`（住所、300 文字まで）のどちらか一方です。両方、またはどちらも指定しないと入力の誤りです。

## 手元のデータと外への問い合わせ

Sora は、日本郵便の 2 つのデータ（一般の郵便番号 `utf_ken_all.zip` と、事業所の `jigyosyo.zip`）を、1 つの SQLite のファイルにして持ちます。行の種類は、一般（`general`）、事業所（`office`）、私書箱（`po_box`）です。町字との結びつけには、ABR の町字のデータ（市区町村ごと）を使います。

データは、使われたときに取得します。確認日時から 7 日を過ぎると、使われたときに裏で取得元を確かめ、変わっていれば作り直します。取得したデータが想定より小さいときは、取得元の形式が変わったとみなして、公開しません。保存先と運用は [address-data.md](../operations/address-data.md) にあります。

利用者の要求に答えている間に外へ問い合わせるのは、データがまだ無いときだけです。データがあれば、外には出ません。

## 決め方

### 郵便番号から住所（順引き）

1. 郵便番号を 7 桁の数字にそろえます（〒、ハイフン、空白、全角を許す）。7 桁にならなければ入力の誤りです。
2. 番号の行をすべて取ります。無ければ、エラーにせず `count: 0` を返します。
3. 行ごとに、全国マスターで市区町村を探し、`lgCode`（6 桁の全国地方公共団体コード）と、市区町村の代表点（`locationLevel: 2`）を付けます。
4. 一般の行で町域があるものは、市区町村の町字のデータに結びつけます。結びついた町字の点の平均を座標にして、`locationLevel` を 3 にします。町字の ID は `machiazaIds` に入れます。
5. 事業所と私書箱の行は、事業所の住所（都道府県、市区町村、町域、小字・番地など）を住所の正規化にかけて、座標を付けます。1 回の問い合わせで座標を付けるのは 20 件までです。

### 町域と町字の結びつけ

1. 名前の書き方をそろえます。全角と半角、漢数字（「三十二」を 32）、「大字」「字」「丁目」の除去、「ヶ」と「ケ」、「ッ」と「ツ」、「ノ」「の」と「之」、空白です。
2. ABR の町字を、大字、小字、大字と小字、大字と丁目の名前で引けるようにします。
3. 次の行は結びつけません。事業所、町域が空の行（市区町村の既定の番号）、注記に「階」を含む行（ビルの階ごとの番号）です。町域の末尾の「一円」は外します。
4. 注記が丁目の範囲（「１〜１９丁目」「８丁目」）の行は、丁目の番号がその範囲にある町字に結びつけます（`exact`）。
5. 注記が無い行と「次のビルを除く」の行は、同じ名前の町字すべてに結びつけます（`exact`）。
6. 注記が「その他」の行は、4. で使われなかった町字に結びつけます（`exact`）。
7. それ以外の注記の行は、同じ名前の町字に結びつけますが、`exact` にしません。

### 住所から郵便番号（逆引き）

1. 住所を正規化します（[address-normalization.md](address-normalization.md)）。市区町村まで読めなければ、番号は返しません。
2. 町字まで読めていれば、その町字に結びついた行を取ります。
   - 注記が番地の範囲（「１〜１０番地」）か番地の列挙（「３６４９、３６６１」）の行は、住所の番地が入るかを調べます。入れば `exact` にします。入らなければ落とします（すべてが入らないときは、落とさずに `exact` でない候補として残します）。判定できない注記は残します。
   - 注記が通り名や建物名の列（京都の「釜座通夷川下る、夷川通釜座東入、…」など）の行は、入力の住所に含まれる項目で絞ります。当たる行があれば `exact` にして、当たらない `exact` でない行を落とします。3 文字未満の項目と、番地の範囲だけの項目は使いません。
3. 町字に結びついた行が無いか、市区町村までしか読めていなければ、市区町村の既定の番号（町域が空の行）を `fallback: true` で返します。
4. 同じ番号は 1 件にまとめて、`exact` のものを先にします。

`exact` は、注記まで読んで、この住所に当たると確かめられたことを表します。`fallback` は、町の専用の番号が無く、市区町村の既定の番号を返したことを表します。

## 決められないとき

この処理は、聞き返しません。候補を並べて返します。

- 順引きで 1 つの番号が複数の町や事業所にまたがるときは、`candidates` に複数入ります。
- 町字のデータが待ち時間に間に合わなければ、座標が市区町村の代表点のままになり、`incomplete: true` と `pending`（例: `city:131016`）が付きます。しばらくして同じ要求を送ると、町字の座標になります。
- 逆引きで住所が読めなければ、`postalCodes` は空です。
- エラーは、住所の正規化と同じです（400 `INVALID_INPUT`、404 `ADDRESS_DISABLED`、502 `ADDRESS_DATA_PENDING`、502 `ADDRESS_DATA_UNAVAILABLE`）。

例です（テストの見本データでの結果の一部です）。

```json
{ "zipcode": "100-0014" }
```

```json
{
  "zipcode": "1000014",
  "count": 1,
  "candidates": [
    { "kind": "general", "prefecture": "東京都", "city": "千代田区", "town": "永田町", "lgCode": "131016", "locationLevel": 3 }
  ]
}
```

市区町村までの住所は、既定の番号を返します。

```json
{ "address": "東京都千代田区" }
```

```json
{ "level": 2, "postalCodes": [ { "zipcode": "1000000", "exact": false, "fallback": true } ] }
```

## 限界

- 注記を読む規則は、丁目の範囲、番地の範囲と列挙、「次のビルを除く」、「その他」、通り名・建物名の列です。それ以外の注記（地割など）は判定できず、候補を `exact: false` で残します。すべての表記を網羅するとは言えません。
- 住所から引く向きは、一般の郵便番号だけです。事業所と私書箱の個別番号は、順引き（番号から住所）でしか出ません。
- ビルの階ごとの番号は町字に結びつけないので、住所から逆引きしても出ません。
- 名前が一致しない町域は、町字に結びつきません。その住所の逆引きは、市区町村の既定の番号になります。
- 一般の行の座標は、結びついた町字の点の平均です。離れた町にまたがる番号では、平均がどの町でもない場所になることがあります。
- 事業所の座標は、住所の正規化の結果に依存します。20 件を超える分は、市区町村の代表点のままです。
- 全国マスターに見つからない市区町村の行には、`lgCode` も座標も付きません。
- 1 つの住所に 1 つの番号が決まるとは限りません。複数の候補を返します。
- データは、日本郵便が更新して、Sora が再確認するまで古いままです。古さは `dataset.updatedAt` と `stale` で分かります。
