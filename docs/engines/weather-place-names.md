# 日本の地名を気象庁の予報区に引き当てる

「天童市」「軽井沢」「横浜市中区」のような地名を、気象庁のデータが使う番号（予報区は 6 桁、市町村は 7 桁）に直す処理です。気象庁の予報と警報の JSON は番号でしか引けません。一方、人が書く地名には、同じ名前の町が複数ある、「市」「町」を省く、郡や町名まで続けて書く、観光地の名前で書く、といった揺れがあります。ここで間違えると、別の県の天気や警報を返してしまいます。そのため Sora は、決められない地名を別の場所の答えに替えず、候補を挙げて聞き返します（v4.1.0 までは、知らない地名を東京に替えていました）。

用語です。

- **予報区**: 気象庁が天気予報を出す単位です。全国で 142 件あり、「村山」「東京地方」「北九州地方」などです。
- **気象台**: 予報と警報の JSON を出す単位です。58 件あります。複数の予報区をまとめて持ちます。
- **市町村**: 気象庁の表にある細かい単位です。1,805 件あります。横浜市のように、気象庁が区域（北部・南部など）に分けている市もあります。
- **気温の地点**: 予報区ごとの、気温を取る観測地点の名前です（村山なら「山形」）。

## 使うツール

| 用途 | MCP | REST |
|---|---|---|
| 天気予報 | `get_weather` | `POST /weather`、`GET /weather`、`GET /weather/:city` |
| 警報・注意報 | `search_disaster_warnings` | `POST /disaster/warnings` |

- 天気は、地名を予報区に直して、その予報区の予報を返します。市町村の単位では返しません。`city` には 6 桁の予報区の番号も書けます。
- 警報は、市町村に当たればその市町村の警報だけを返します。`areaCode`（7 桁の市町村、6 桁の予報区か気象台、2 桁の都道府県）でも指定できます。
- `GET /weather` で `city` を省くと東京です。警報で `city` も `areaCode` も省くと東京地方です。

## 手元のデータと外への問い合わせ

手元のデータは 2 つです。

- `src/jma_areas.ts`: 気象庁の `area.json` と各気象台の予報 JSON から、2026-11-06 に取得して作った表です。予報区 142 件、気象台 58 件、市町村 1,805 件（名前は 1,775 種類）と、予報区ごとの気温の地点の名前を持ちます。作り直しは `scripts/jma-areas/` のスクリプトによる手作業で、自動では更新されません。
- `src/city_map.ts`: 地名から予報区への表で、3,456 件あります。市町村名と省略形、観光地の名前（箱根、軽井沢など）、都道府県名、予報区の最初の気温の地点の名前（横浜、八幡など）を持ちます。livedoor 天気互換の地点定義を元にして、気象庁の市町村の表と食い違わないように突き合わせてあります。複数の市町村に当たる名前（府中、森町など）は載せません。

地名の解決そのものは、外に問い合わせません。外に出るのは、解決した番号で予報や警報を取るときだけです。

- 天気: 気象庁の `forecast/data/forecast/{気象台}.json` と `overview_forecast/{気象台}.json`
- 警報: 気象庁の `warning/data/r8/{気象台}.json`（2026 年 5 月下旬の気象庁の新しい防災気象情報に合わせて、v4.1.0 で旧いデータから移しました）

結果は、解決した番号ごとにキャッシュします（天気は日数も合わせて 1 時間、警報は 5 分）。入力の書き方が違っても、同じ番号なら同じキャッシュです。REST では `noCache: true` で、キャッシュを使わずに取り直せます。

## 決め方

天気も警報も、地名は同じ関数（`resolvePlace`）で解決します。入力の空白は、どこにあっても取り除きます。

1. **市町村の名前そのまま。** 当たる市町村が 1 つなら決まりです。区域に分かれた市は、区域を合わせた市全体を 1 つの市町村として扱います。
2. **地名の表（`city_map.ts`）。** 当たれば、その予報区です。都道府県名もこの表にあり、県の代表の予報区になります（北海道だけは表にありません）。警報のときだけ、地名に「市」か「区」を足した市町村が同じ予報区に 1 つだけあれば、その市町村にします（「横浜」は横浜市。「八幡」は京都府の八幡市が別の予報区なので、北九州地方のままです）。
3. **気象庁の予報区と気象台の名前。** 予報区の名前は、「地方」を除いた形（「十勝」）と、2 つ目以降の気温の地点の名前を含みます。いくつかの県に同じ名前がある予報区（「東部」）は、「神奈川県東部」のように都道府県名を付けたときだけ当たります。ほかの予報区の市町村にも当たる名前（「上野」「池田」「日高」）は、市町村と予報区を挙げたエラーです。気象台の名前（「上川・留萌地方」）は、含まれる予報区を挙げたエラーです。
4. **市町村の表の規則。** 次の読み方で市町村を探します。複数残れば、候補を挙げたエラーです。
   - 先頭の都道府県名で絞る（「北海道森町」）。
   - 政令指定都市の区は市全体にする（「横浜市中区」は横浜市）。神戸市や広島市の区は、区ごとの区域があるのでそのままです。
   - 「市」「区」「町」「村」は省いてよい（「札幌」は札幌市）。
   - 郡の付いた住所は、郡の後ろの町村で引く（「北海道上川郡上川町」は上川町）。「蒲郡市」のように郡が市町村名の中にある場合と、「山口市小郡栄町」のように先頭の市・区の後ろにある郡は、郡として扱いません。
   - 都道府県名だけの入力がここまで来るのは北海道だけです。気象台が複数あるので、予報区を挙げたエラーにします。
5. **一部一致。** 地名の後ろに町名などが続く入力を、次の順で引きます。
   - 先頭の都道府県名は、後ろに 2 文字以上続くときだけ外し、その都道府県の中で後ろを引く。後ろが何にも当たらなければ、その都道府県の代表の予報区にする（北海道は代表の予報区が無いので、見つからないエラー）。
   - 2 文字以上の入力が地名の書き出しか、区域に分かれた市町村の名前の後ろに当たるときは、当たる地名がすべて同じ予報区のとき（同じ市町村の区域どうしなら、予報区が違っても最初の区域）だけ採る（「富士河口」は富士河口湖町）。
   - 郡の後ろに市町村の名前があれば、その市町村で引く（「足柄上郡中井町比奈窪」は中井町）。
   - それ以外は、入力のいちばん前から始まる地名（同じ位置なら長い方）を 1 から 4 の規則で引く（「日光市中宮祠」は山口県の光市でなく日光市）。ほかの地名の途中や重なりは拾いません。
   - 「〜島」（「〜半島」を除く）で終わる入力は、都道府県名か市区町村の名前で始まるとき、または「〜島」の名前で始まるときだけ、この規則を使います。「小浜島」を福井県の小浜市にはしません（主な島は地名の表に入れてあります）。
6. どれにも当たらなければ、見つからないエラーです。

警報だけの手順が、この前にあります。

- `areaCode` があれば、それを使います（`city` は見ません）。区域に分かれた市は、区域の 7 桁をカンマでつないだ値も受けます（例: `1410011,1410012`）。
- `city` が空白だけなら、`areaCode` が無い限りエラーです。6 桁の数字の `city` は、予報区か気象台の番号として扱います。
- 都道府県名（略称も）は、県全体です。県の予報区をすべて合わせます（予報区の 1 つにすると、ほかの予報区の警報を落とすためです）。気象台が複数ある北海道・鹿児島・沖縄は、気象台を挙げたエラーです。
- 気象台の名前は、その範囲の予報区すべてです。

警報の中身は、気象庁の報を 33 種類の番号の表（`WARNING_KINDS`）で読み、次のように組み立てます。

1. 解決した範囲の欄（市町村なら市町村の欄、予報区なら予報区の欄）をすべての報から集める。
2. 「解除」と「発表警報・注意報はなし」を除く。
3. 同じ種類は 1 つにまとめ、状態は「発表」を「継続」より先にする。
4. 大雨・土砂災害・高潮には段階（レベル 2 から 5）を付ける。
5. 河川の氾濫は読みません。

天気は、予報区の番号から気象台を選びます（十勝は別の気象台の JSON にあります）。気温は予報区の最初の気温の地点で、地点の名前を `temperatureArea` で返します。3 日目以降の週間予報は、その予報区を含む地域（「中部・南部」など）のものです。

## 決められないとき

決められない地名は、エラーにして候補を挙げます。REST は 400（`INVALID_INPUT`）、MCP は `isError` の応答です。

```json
{ "city": "府中" }
```

```text
地名「府中」に当たる市町村が複数あります（東京都府中市、広島県府中市、広島県府中町）。都道府県名や市・区・町・村まで付けてください
```

利用者は、次のように言い直します。

```json
{ "city": "東京都府中市" }
```

エラーになるのは次の場合です。

- 同じ名前の市町村が複数ある（「府中」「森町」「川崎」）。
- 市町村と予報区の両方に当たる（「上野」「日高」）。
- 「北海道」のように、予報区が 1 つに決まらない都道府県名。予報区の一覧を挙げます。
- 気象台の名前。含まれる予報区の一覧を挙げます。
- 表にも規則にも無い地名（「お台場」など）。

`days` は 1 から 8 の整数で、省くと 7 です。範囲外は 400 です。

## 限界

- 予報は予報区の単位です。同じ予報区の中の山間部と沿岸部の違いは出ません。気温も予報区の 1 つの地点のものです。
- 表は 2026-11-06 時点のものです。気象庁が区域を変えると、作り直すまで食い違います。警報は、表と気象庁のデータが食い違って欄が無いとき、「警報なし」ではなくエラーを返します。天気は食い違いを検知せず、気象庁の JSON にその予報区の番号が無いと、最初の予報区の値を返します。
- 気象庁がデータの形式を変えると、古い答えを返し続けることがあります。実際に、2026 年 5 月下旬に気象庁が新しい防災気象情報へ移ったあと、Sora は旧いデータを読み続け、数か月前の警報を今の警報として返していました（v4.1.0 で直しました）。
- 河川の氾濫の警報は含みません。「警報なし」は、氾濫の情報が無いことを意味しません。
- 「地名として読む語」の判定は、表と規則によるものです。網羅的な地名の理解ではありません。表に無い地名（「お台場」）は引けません。旧国名や地方名を前に付けた名前（「安芸府中」「東北郡山」）と郡の名前だけの入力（「足柄上郡」）は、前の語や郡の名前の一部が別の県の市町村に当たることがあります。「東北郡山」は、福島県の郡山でなく青森県の予報区に当たります。都道府県名を付ければ避けられます。
- 都道府県名で始まる入力は、後ろが表のどの地名にも当たらなくても、その都道府県の代表の予報区になります（「静岡県あああ」は静岡県の中部）。北海道だけは代表の予報区が無いので、見つからないエラーです。後ろが読めなかったことは、応答から分かりません。
- 「高原」は宮崎県の高原町の名前ですが、「美ヶ原高原」のように地名の後ろに付く言葉でもあるため、一部一致には使いません。

## 実装とテスト

- 解決の規則: `src/services/jma_area.ts`
- 気象庁の表: `src/jma_areas.ts`（`scripts/jma-areas/gen_jma_areas.ts` と `assign_points.ts` で生成）
- 地名の表: `src/city_map.ts`
- 天気の取得: `src/services/life.ts`
- 警報の取得: `src/services/disaster.ts`
- REST の入口: `src/routes/public_data.ts`
- テスト: `src/city_map.test.ts`、`src/services/life_weather.test.ts`、`src/services/disaster.test.ts`

空港・都道府県・道路の名前の解決は、別の処理です（[airport-road-names.md](airport-road-names.md)）。
