# X の投稿検索で固有名詞を落とさない

Sora は X（旧 Twitter）の投稿を、Yahoo! リアルタイム検索を通して探します。「ライブ 予定 サンプルスターズ」のように語を並べた検索語は、すべての語がそろう投稿が少なく、語を 1 つ減らして検索し直す普通の緩和では、肝心の固有名詞を落として無関係な投稿ばかりを返すことがあります。Sora は、本人・公式の投稿を優先するか第三者の投稿を優先するか（focus）、落としてはいけない固有名詞はどれか（anchor）、どの投稿をいくつ返すか、を自前の規則で決めます。

## 使うツール

- MCP: `search_realtime`、`search_deep` の X の部分（`includeRealtime`・`realtimeFocus`・`realtimeAnchor`・`realtimeLimit`・`officialAccountId`）
- REST: `POST /search/realtime`・`POST /realtime`、`POST /search`・`/search/deep`・`/search/integrated`・`/deep-search`（この 4 つは `search_deep` と同じ処理です。[search-evidence.md](search-evidence.md) を見てください）

## 手元のデータと外への問い合わせ

投稿そのものは手元に持ちません。手元にあるのは、コードの中の語彙だけです（`src/retrieval/lexicons/realtime_focus.ts` ほか）。

- 第三者の投稿を優先する目印の語 21 語（評判・口コミ・感想・反応・炎上・批判など）と、そのうち検索語から外す 6 語
- 固有名詞になりにくい語: 意図語 48 語（[search-evidence.md](search-evidence.md) の語彙と共通）と、「明日」「予定」「公式」「タイムテーブル」などの 14 語

目印の語は、実際の投稿数を測って決めました。「評判」「口コミ」は投稿にほとんど書かれず、「感想」「反応」「炎上」などは書かれます。

外への問い合わせは次のとおりです。

- Yahoo! リアルタイム検索。検索 1 回で取るのは既定 20 件、最大 40 件です。
- 固有名詞を決めるときだけ、Web 検索（上位のタイトルを見ます）と、候補の語ごとの X の総ヒット数。総ヒット数は 24 時間覚えます。`search_deep` では、同時に走る Web 検索を使い回します。
- 固有名詞が壊れているとき（下の 4）だけ、公式アカウントを探す Web 検索（x.com に絞ります）と、そのアカウントの最近の投稿 20 件。
- 本文が 240 字以上で切れていそうな投稿（先頭 10 件のうち、問いの語に合うもの）だけ、全文を補う外部サービス（FxTwitter）に最大 2 件、1.5 秒で諦めて問い合わせます。

`search_realtime` の応答は 2 分覚えます（一部の検索が失敗した応答は覚えません）。

## 決め方

1. **誰の投稿を優先するか（focus）を決める。** 問いに目印の語があれば `public`（本人以外。評判・感想・炎上・現地の様子）、なければ `official`（本人・公式。予定・告知・事実確認）です。呼び出し側が `focus` を指定すれば、それを使います。`public` のとき、目印の語は必須の語にしません。投稿にほぼ書かれない語は検索語から外し、書かれる語は「語つき」と「語なし」の 2 つの検索を並行して行って、語つきの投稿を先に並べます。
2. **1 回目の検索（wave 1）をして、そろったかを見る。** 検索は、並行して行う最大 2 つの検索を 1 まとまり（wave）として、最大 3 まとまり行います。1 回目は元の検索語（と、`id:` などを先頭に動かした同じ意味の検索語）です。検索語から、`id:`・`@`・`#`・`-` の付いた語と OR の括弧を除いた残りが、必要な語です。1 件の投稿の中（表示名・アカウント名・本文）に必要な語がすべてあれば、そろったとみなします。全角・半角と大文字・小文字は区別しません。
   - そろった投稿が 1 件でもあれば終わりです。ただし、投稿が 6 件以上あり、そろった投稿が半数未満なら、まだ終わりにせず、固有名詞を調べます（壊れていなければ、そのまま終わります）。1 件だけ偶然そろっても、ほかが別物かもしれないためです。
   - OR・URL・引用符を含む式と、2 ページ目以降は、式の意味を変えないよう、元の式を 1 回検索して終わります。
3. **固有名詞（anchor）を決める。** そろわなかったときだけ決めます。
   1. 呼び出し側が `anchor`（`search_deep` は `realtimeAnchor`）を指定していて、検索語のどれかに対応すれば、それを使います。対応は、空白・中黒・全角半角を無視して同じ語、なければ指定に含まれる語（「Sample Stars」に対する「Sample」）です。対応する語がなければ、指定は無視して次へ進みます。
   2. 候補は、意図語・上の 14 語・数字や時刻・第三者の目印の語を除いた語です。全部が除かれたら、全部の語を候補にします。候補が 1 つなら、それが固有名詞です。
   3. 候補が 2 つ以上なら、点を付けます。Web 検索の上位 10 件のタイトルに語が出れば 1、タイトル末尾のサイト名の枠にも出れば、さらに 2 を足します。総ヒット数が全候補分取れたときは、これを ln(総ヒット数 + e) で割ります。ありふれた語の点が下がります。
   4. 最高点の 85% 以上の語のうち、総ヒット数が最高点の語の 3 分の 1 以下の語があれば、その語（複数なら最も少ない語）を選びます。「ライブ」と固有名詞がほぼ同点でも、固有名詞を選べます。
   5. 次の場合は、決めません。最高点が 0 以下。最高点が同点。総ヒット数が全候補分あるのに、最高点の語が少ない側の半分にも入らず、最少の語の 1.25 倍以内でもない（「持ち物」のような一般語）。決めなかったときは、従来の緩和に任せます。語を誤って守るより、守らないほうが害が小さいためです。
4. **固有名詞が壊れていないか見る。** 1 回目の検索の投稿のうち、固有名詞を含むものが半数未満なら、壊れているとみなします（Yahoo が記号を無視して別物を返す語。たとえば架空の「=SPICA」が、記号を無視されて一般の「SPICA」の投稿になる）。
   - 公式アカウントは、Web 検索の結果のうち、タイトルに固有名詞を含む x.com のアカウントから探します。見つからなければ、固有名詞を x.com に絞って検索します。その最近の投稿 20 件のハッシュタグから、別名を探します。先頭の日本語の部分（2 文字以上）を候補にし、その語で始まるタグを含む投稿が 2 件以上かつ 30% 以上あるものを採ります（「#スピカ」なら「スピカ」）。
5. **緩和して検索し直す（wave 2・3）。** 語を 1 つずつ落とした検索語を作ります。足りない語を多く残す候補から先に試します。固有名詞は落としません。`id:` などの付いた語は残します。
   - 別名が見つかっていれば、別名に置き換えた全語の検索から始めます。
   - 1 つの wave で試すのは 2 検索までで、全体で 5 検索までです。
   - wave 3 では、固有名詞を決めていれば、不足した語の単独検索の代わりに、固有名詞だけで検索します。
   - そろう投稿が出た時点で止めます。
   - 固有名詞が壊れていたときは、最後に、固有名詞も別名も含まない投稿を除きます。
6. **同じ投稿をまとめる。** 投稿の同一性は、投稿の ID、URL にある投稿の ID、正規化した URL、補助のキー（投稿者・時刻・本文の先頭 240 字）の順で決めます。本文だけでは決めません。本文が同じでも ID が違えば別の投稿です。検索の結果は、検索を計画した順に統合します。終わった順ではありません。同じ投稿を返した検索の順位は RRF の点にして記録しますが、並びには使いません。投稿は検索元の順のままです。
7. **返す件数を決める。** `limit`（既定 20、最大 40）は、検索 1 回で取る件数であり、返す件数の上限でもあります。`search_deep` の `realtimeLimit` は返す件数の上限で、20 を超えるときは取る件数も増やします（1 回の取得は 40 件まで）。上限を超えるときは、検索ごとに交互に選びます（`public` では同じ投稿者を後回し）。ただし、上限内のどの投稿にもない必要な語を含む投稿は、上限を超えて最大 5 件まで残します。省いた件数は `omittedCount` です。
8. **公式枠を足す（`search_deep` だけ）。** 公式アカウントは、`officialAccountId`、Web 検索の結果にある x.com のアカウント、読んだページのメタタグで宣言されたアカウントの順に探します。固有名詞が決まったときは、公式枠もその固有名詞の公式アカウントにそろえます。自動で見つけたアカウントは、表示名か 3 割以上の投稿に必要な語がある場合だけ、公式として使います（`officialAccountId` を指定したときは確かめません）。公式の投稿は、`official` のとき先頭に最大 5 件、`public` のとき後ろに最大 2 件を、上限とは別に足します。

## 決められないとき

聞き返しはしません。結果の状態は、応答の次の項目で伝えます。

- `missingTerms`: 1 件の投稿にそろわなかった語（空なら省略）
- `aliasTerms`: 固有名詞の代わりに検索した別名（使ったときだけ）
- `omittedCount`: 上限で省いた投稿の数
- `focus`: 実際に使った優先の向き

例（架空）: 「ライブ 予定 =SPICA」で、公式の投稿にだけ「=SPICA」が正しく書かれているとき。

```json
{
  "focus": "official",
  "aliasTerms": ["スピカ"],
  "count": 20,
  "omittedCount": 7
}
```

「ライブ」と「=SPICA」は点がほぼ同じでも、総ヒット数が大きく違うので、「=SPICA」を固有名詞に選びます。Yahoo が「=」を無視するため、公式のハッシュタグから別名「スピカ」を見つけ、それで検索し直した、という意味です。

検索元が制限中のときは、そこで検索を止めます。一部の検索が失敗したときは、成功した分を返し、`partial: true` と `providerErrors` を付けます。すべて失敗したときは、0 件の成功にせず、エラー（REST は HTTP 502、MCP は `isError`）にします。止まった理由（`stopReason`）と使った検索語は、`verbose: true` で見られます。

## 限界

- 固有名詞の判定は、評価セットで確かめた範囲の精度です。dev と held の 53 クエリでは、誤りが 0 件（正解 50、決めない 3）でした。方式を決めたあとに、正解を先に決めて集めた 16 クエリでは、正解 9、決めない 5、誤り 2 です。誤りは、固有名詞のない「前方エリア 一般エリア 違い フェス」で、「前方エリア」という名詞句を選んだものです。
- 判定は、Web 検索のタイトルと X の総ヒット数に頼ります。どちらも検索のたびに変わり、新しい名前や話題の少ない名前では、決められないことがあります。決められなければ、従来の緩和になり、固有名詞が落ちることがあります。
- 語彙は網羅ではありません。第三者の目印は 21 語です。「ひどい」「最高」のような語は、目印になりません。
- 別名は、公式アカウントの最近の投稿のハッシュタグから見つけます。公式アカウントが見つからない、またはタグを使っていなければ、別名は見つかりません。
- 公式アカウントの自動判定は、表示名か投稿の語で確かめます。別の名前で運用している公式は、公式として使えないことがあります。
- 検索結果の件数や順位は、Yahoo! リアルタイム検索のものです。Sora は、投稿の網羅も真偽の確認もしていません。
- `SORA_REALTIME_ANCHOR=off` で、固有名詞の判定を止めて、従来の緩和に戻せます。
