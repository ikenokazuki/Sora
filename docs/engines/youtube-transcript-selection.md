# 長い字幕から問いに関係する部分を選ぶ

長い動画の字幕は、そのまま返すと量が多く、AI の読む量が増えて、答えのある部分が埋もれます。Sora は、字幕を 30 秒ほどの段落に分け、問いの語に関係する段落を字数の予算の中で選びます。語が出る段落だけを拾うと、同じ話題が続く隣の段落を落とすので、話題のつながりも見て選びます。

## 使うツール

選ぶ処理を使うのは、次の 3 つです。どれも、`youtube` モジュールが有効なときだけ使えます。`ENABLED_MODULES` が未設定か `all` なら有効です。

- `scrape`（`urls` の一括取得・`search_web` の `formats`・`search_deep` の本文取得も同じ）に YouTube の動画 URL を渡したとき。字幕が `maxChars` に収まらなければ、`query` に関係する段落を選びます。
- `search_video` の `transcripts`（上位の YouTube 動画の何本に字幕を付けるか。0〜5、既定 0）と `transcriptChars`（1 本あたりの最大字数。500〜10,000、既定 2,000）。REST は `POST /search/video` です。
- `search_deep` の `videos`（0〜5、既定 0）。

`get_youtube_transcript`（REST は `POST /youtube/transcript`）は、問いで選びません。`fromSec`（既定 0）から `maxChars`（既定 30,000）までを返し、続きは `nextFromSec` で読みます。`get_youtube_channel` は動画の一覧を返すだけで、字幕は読みません。

## 手元のデータと外への問い合わせ

手元のデータは、コードの中の定数だけです。HMM の定数 5 つ（下の「決め方」）のほか、段落の区切りと BM25 の定数があります。字幕は事前に集めません。起動時の処理も、常駐するタイマーもありません。

外へは、呼ばれたときに YouTube へ問い合わせます。動画の題名・説明文・チャプターと、字幕の一覧、字幕の本文を取ります。取り方は YouTube の公開 API ではないため、YouTube の変更で止まることがあります。結果は 30 分、手元のキャッシュに残します。字幕がなかった結果は 60 秒だけ、取得に失敗した結果は残しません。

`search_video` と `search_deep` の `videos` では、動画を見つけるために Yahoo! の動画検索も使います。

## 決め方

### 字幕を段落にする

1. 字幕を、約 30 秒か 300 字ごとの段落に分けます。先に来たほうで区切ります。同じ秒に始まる字幕は、字数を超えても分けません。各段落には開始秒を付けます。
2. 返すときは、1 段落を 1 行にして、先頭に `[m:ss]` を付けます。

### どの字幕を使うか

1. 言語の候補を、指定の言語（既定 `ja`）、元の音声の言語、英語の順に並べます。候補ごとに、手動字幕を先、自動字幕（YouTube の音声認識）を後にして探します。言語コードが完全に同じものを先、基本の言語が同じもの（`zh-Hant` なら `zh`）を後にします。最後に、残りの手動字幕、残りのすべての字幕の順に並べます。
2. 指定の言語が日本語（既定）で、題名に仮名がある動画に、日本語以外の自動字幕しかないときは、使いません（中身が意味をなさないことがあるため）。
3. 選んだ字幕の中身が空なら、次の候補を試します。取得に失敗したら、そこで止めます。

### 関係する段落を選ぶ

1. **点を付ける。** 各段落に、見出し階層ボーナス付きの BM25（語の出現数と段落の長さから点を付ける、検索で広く使う式。k1=0.9、b=0.4）で点を付けます。問いからは、語と、隣り合う語をつないだ語を作ります。動画にチャプターがあれば、段落が入るチャプターの名前を見出しとして加点します。チャプターは、説明欄の時刻つきの一覧で、0:00 から始まるものだけを数えます（ライブ告知の「17:00 開場」を拾わないため）。
2. **どの段落にも点がなければ、先頭から選ぶ。** この場合、応答の `excerpt` は `head` になります。
3. **チャプターがなければ、話題のつながりで順位を付ける。** 段落ごとに「問いの話題を話している最中か」を 2 つの状態で考える、隠れマルコフモデル（HMM。Jiang & Zhai, 2006）を使います。前から後ろ、後ろから前の両方向の計算で、各段落が話題の最中にいる確率（事後確率）を出します。
   - 話題の最中の段落は、次の段落も話題の最中である確率を 0.9 とします（話題の最中でないほうも、次も同じである確率は 0.9）。
   - 最初の段落が話題の最中である確率は 0.1 とします。
   - 段落の点が高いほど、話題の最中だと考える度合いを上げます。点を最高点で割った値から 0.1 を引き、2 倍して指数にした値が、話題の最中でない場合と比べた、その段落の出やすさです（最高点の段落で約 6 倍、点がない段落で約 0.8 倍）。
   - 事後確率が 0.3 に届かず、段落自身にも点（問いの語の一致）がない段落は、選びません。
   - 話題は何段落も続くので、問いの語が出ない続きの段落の確率が上がり、一言だけ触れた離れた段落の確率は下がります。
4. **チャプターがあれば、HMM は使わず、点の順に選ぶ。** チャプター名の加点のほうが当たります。HMM を使うと精度が下がりました（「限界」を見てください）。
5. **予算まで選ぶ。** 順位の高い段落から、字数の予算に収まる限り選びます。収まらない長い段落は飛ばして、次の段落を試します。最初に選ぶ段落は、予算を超えても入れます。選んだ段落は、時刻の順に並べます。

`search_video` の予算は `transcriptChars` です。`scrape` では、字幕全体が `maxChars` に収まれば全部を載せ、収まらないときだけ選びます。そのとき、字幕は `### 1m23s` の見出しの段落にして本文に載せ、チャプターがあればその見出しの下に並べます。字幕の節の先頭に、字幕全体の字数と、選んだことを示す注意を入れます。この本文から、さらに [検索結果から答えの根拠を選ぶ](search-evidence.md) の仕組みで、ハイライトを選びます。

## 決められないとき

聞き返しはしません。`transcript.status` で状態を伝えます。

| `status` | `reason` | 意味 |
|---|---|---|
| `ok` | なし | 字幕がある。`source` は `manual` か `auto` |
| `none` | `no-captions` | 字幕がない。音声認識はしません |
| `none` | `live-now` | 配信中で、字幕がない |
| `none` | `language-mismatch` | 自動字幕の言語が題名と合わず、返さない。`lang` を指定すれば取れます |
| `unavailable` | `blocked`・`request-failed` | YouTube が拒否した、または通信に失敗した。時間をおいて再試行します |
| `unavailable` | `video-unavailable` | 再生できない動画 |

`get_youtube_transcript` では、再生できない動画は `transcript` がなく、`found: false` と `reason: "video-unavailable"` になります。`ok` 以外のときの `message` には、話している内容を推測で補わないでください、と書いてあります。自動字幕には `note` が付き、聞き間違いを含むことと、引用するときは自動字幕と伝えることを求めます。

例（架空）: `search_video` に `query: "サンプル講座 第3回 試験範囲"`、`transcripts: 1` を渡したときの、1 本目の `transcript` です。

```json
{
  "status": "ok",
  "source": "auto",
  "language": "ja",
  "excerpt": "relevant",
  "text": "[12:05] …\n[12:35] …\n[13:10] …",
  "chars": 1480,
  "totalChars": 41200
}
```

字幕全体は 41,200 字あり、問いに関係する 3 段落（1,480 字）を時刻順に返した、という意味です（数字は架空です）。全体は `get_youtube_transcript` で読めます。`excerpt` が `head` なら、問いの語がどの段落にもなく、先頭から返しています。

## 限界

評価は、説明欄にチャプターが 5 個以上ある動画（集めた 37 本のうち 18 本）で、チャプターを外してチャプターのない動画を再現し、チャプターの時間帯を正解にして測りました。dev が 9 本（49 問）、held-out が 9 本（52 問）です。選んだ字数のうち正解に入る割合（精度）、正解の字数のうち選べた割合（取れた割合）、1 位の段落が正解に入る割合は、次のとおりです。

| 方式（held-out、チャプターなし） | 精度 | 取れた割合 | 1 位 |
|---|---|---|---|
| 段落ごとの BM25 だけ | 0.408 | 0.471 | 0.365 |
| HMM（採用） | 0.438 | 0.696 | 0.538 |

- 取れた割合は +0.230（95% 信頼区間 +0.172〜+0.307）、1 位は +0.212（+0.082〜+0.321）で、差があります。精度の差（+0.026）は、差があるとは言えません。
- チャプターがあるときに HMM を使うと、精度が 0.704 から 0.637 に下がったので、使いません。
- 学習する CRF（条件付き確率場。段落の並びから、話題の最中かどうかを学習して決める方法）は、1 位が 0.654 と高かったものの、精度と取れた割合には差がなく、学習が要らない HMM を採りました。
- 正解は動画の作者が付けた区切りです。チャプターの題名が字幕に出ない動画では、どの方式も当たりにくくなります。
- HMM の定数 5 つは、dev の 9 本で決めました。小さな評価です。
- 語の一致で選ぶので、話し言葉の言い換えや、自動字幕の聞き間違いで問いの語が一致しないと、見つけられません。
- 予算が狭く、問いの語が出る段落が少なくて離れているときは、離れた所の一言のほうが、本題の途中の段落より上に来ることがあります。
- 段落は約 30 秒・300 字で機械的に分けます。話題の切れ目とは合いません。
- 字幕のない動画は読めません。
