# 住所データ基盤 運用手引（Address Data Operations）

デジタル庁アドレス・ベース・レジストリ（ABR）および日本郵便の一次データを活用した、オンデマンド・市区町村単位の住所データ基盤の構成・設定・運用手引です。

---

## 1. 概要とアーキテクチャ

本機能は、外部のジオコーディング API やサードパーティサービスに過度に依存せず、高精度な住所正規化（住居表示・地番・番地号までの level 8 対応）、郵便番号検索、逆ジオコーディングをローカルで高速に実行するための基盤です。

### 主な特徴
- **使わない環境に負担をかけない**: サーバー起動時の通信・データ取得・子プロセス起動は一切行いません（運用者が `SORA_ADDRESS_PRELOAD` を指定した場合を除く）。使われない環境ではファイル作成も子プロセス起動もゼロです（`SORA_ADDRESS=off` ならツールの登録もしません）。
- **オンデマンド・市区町村単位の遅延ロード**: 全国一括ダウンロード（住居表示で約 480MB、地番で約 10GB と推定）を行わず、要求があった市区町村（6桁自治体コード単位）のデータのみを順次取得・構築します。
- **軽量な分離子プロセス**: データのダウンロード、ZIP 解凍、CSV 結合、SQLite 構築は、優先度を落とした専用子プロセス（`address-build.js`、nice 10）で実行され、本体サーバーのイベントループやメモリを圧迫しません。
- **自動世代管理とディスク予算**: 一時ディレクトリで検証した後に原子的（atomic）に反映。設定されたディスク予算（既定 2GB）を超過した場合は、最終利用日時が古い市区町村から安全に破棄（LRU evict）します。

## 2. 環境変数と設定項目

すべての設定は環境変数経由で行います。`SORA_ADDRESS` は MCP ツールの登録時（サーバー起動時）に、その他の値は住所機能を初めて使うときに読み込まれます。

| 環境変数 | 型 / 選択肢 | 既定値 | 説明 |
| :--- | :--- | :--- | :--- |
| `SORA_ADDRESS` | `lazy` \| `eager` \| `off` | `lazy` | 住所機能の動作モード。<br>・`lazy`: `search_postal_code` / `normalize_address` / `reverse_geocode` が呼ばれたときだけ、必要な市区町村を取得する。`get_elevation` / `search_poi` の座標解決は、**取得済みのデータだけ**をローカル優先で使い、取得は頼まない。<br>・`eager`: `lazy` に加えて、座標解決でデータの無い地域を見つけたとき、**待たずに**裏で取得を始める（その回は従来の経路で答える）。<br>・`off`: 住所機能を無効化。3 ツールを登録せず、REST は 404 `ADDRESS_DISABLED` を返す。取得も子プロセスも起こさない。 |
| `SORA_ADDRESS_DIR` | パス文字列 | `<db_dir>/address` | 住所データの保存先ディレクトリ。未設定時はデータベースファイル（本番は `/data/sora.db`）と同階層の `address/`、つまり本番では `/data/address`。 |
| `SORA_ADDRESS_MAX_MB` | 数値 (64〜1048576) | `2048` (2GB) | ディスク使用量の上限（MB）。超過時は古い市区町村データから自動回収。 |
| `SORA_ADDRESS_WAIT_MS` | 数値 (1000〜120000) | `20000` (20秒) | 初回データ構築の待機上限（ミリ秒）。上限を超えた場合は暫定結果（`incomplete: true`）を返し、バックグラウンドで構築を継続。 |
| `SORA_ADDRESS_BUILD_CONCURRENCY` | 数値 (1〜4) | `1` | 子プロセスによるデータ構築ジョブの並行実行数。CPU/メモリ負荷を抑えるため既定は 1。 |
| `SORA_ADDRESS_PRELOAD` | 都道府県コードのカンマ区切り、または `all` | 未設定 | 事前取得する範囲（例: `13,14` は東京都と神奈川県、`all` は全国）。指定した運用だけ、サーバー起動の10秒後から、その範囲の市区町村を低優先度で順に取得して残す。止まっても次の起動で続きから進む。詳細は §4。未設定なら起動時に何もしない。 |

## 3. ディレクトリ構成と status.json

`SORA_ADDRESS_DIR` 配下は以下の構造で管理されます：

```text
address/
├── status.json                  # 全成果物のメタデータ（版、サイズ、利用日時、エラー記録）
├── lock                         # 構築中ジョブの排他ロックファイル
├── preload.json                 # 事前取得（SORA_ADDRESS_PRELOAD）の進み具合。指定した運用だけに作られる（§4）
├── master/<ver>/ja.json         # 全国マスター（都道府県・市区町村・代表点座標）
├── postal/<ver>/postal.sqlite   # 一般の郵便番号と事業所の個別郵便番号（SQLite）
├── index/<ver>/geo.sqlite       # 逆ジオコーディング用の町字代表点の索引（SQLite、0.01 度の格子）
├── city/<lg_code>/<ver>/        # 市区町村の町字（段A）: town.json
├── num/<lg_code>/<ver>/         # 市区町村の番地・号（段B）: rsdt.txt（住居表示）、chiban.txt（地番）、ranges.json（町字ごとの節の位置）
└── tmp/                         # 構築中の作業ディレクトリ
```

### `status.json` の確認方法
`status.json` には各成果物の状態が JSON 形式で記録されます（時刻はエポックミリ秒）：
```json
{
  "version": 1,
  "seq": 7,
  "artifacts": {
    "master": {
      "ver": "mv6pl05i-q9ac",
      "sig": "9fd0088af7a7b668",
      "sourceDate": "2024-03-14",
      "builtAt": 1791897629958,
      "checkedAt": 1791897629958,
      "usedAt": 1791897629987,
      "bytes": 312502
    },
    "city:131016": { "ver": "mv6pl0e8-jlwn", "sig": "3f41287cfb5b77e9", "sourceDate": "2026-03-10", "bytes": 20201 }
  },
  "failures": {}
}
```
- 成果物の ID は `master` / `postal` / `index` / `city:<lg_code>`（町字）/ `num:<lg_code>`（番地・号）。
- `sourceDate`: 取得元（デジタル庁または日本郵便）の最終更新日。API レスポンスの `dataset.updatedAt`（使ったデータのうち最も古い更新日）に反映されます。
- `error` / `errorAt`: 直近の再確認の失敗（成果物が既にあるとき）。成果物がまだ無い ID の失敗は `failures` に記録されます。
- `seq`: 公開・破棄のたびに増える番号。

## 4. 事前取得（SORA_ADDRESS_PRELOAD）とデータ構築の手動実行

通常はオンデマンドで自動構築されます。配送などで全国または特定の地域を初回から速く答えたい運用者は、事前に取得しておけます。

### 事前取得（`SORA_ADDRESS_PRELOAD`）

```bash
# 東京都と神奈川県の市区町村を、サーバー起動後に取得して残す
SORA_ADDRESS_PRELOAD=13,14
# 全国（地番を含めて数GB規模。SORA_ADDRESS_MAX_MB を増やすこと）
SORA_ADDRESS_PRELOAD=all
```

- 指定したときだけ、サーバーの起動から10秒後に始まります。指定が無ければ、モジュールの読み込みも通信もありません。`SORA_ADDRESS=off` なら指定があっても何もしません。
- 先に全国マスター・郵便番号・逆ジオコーディングの索引（合計約 40MB）を揃え、そのあと範囲内の市区町村を、コード順に1件ずつ（町字、番地・号の順に）取得します。構築は通常と同じ子プロセス（低優先度）で、1件ずつ頼むので、利用者の要求は待ち行列に割り込めます。
- 取得できた成果物には印（`pinned`）を付けます。範囲内で印のある成果物は、ディスク予算（`SORA_ADDRESS_MAX_MB`）を超えても破棄されません。指定を狭めたり外したりすると、範囲外になった印は効かなくなり、通常どおり古いものから破棄されます。
- 予算に空きが無くなる（次の市区町村の分として約 16MB を見込む）と止めます。`SORA_ADDRESS_MAX_MB` を増やして再起動すると、続きから進みます。
- 取得に失敗した市区町村は飛ばして次へ進みます（失敗のたびに 30 秒から 5 分まで間隔を延ばす）。失敗が5回続いたら止めます。国外 IP の拒否（403）はその場で止めます。
- 再起動しても、確認が24時間以内の成果物は取り直しません。24時間を超えていれば、署名だけ確かめます（変わっていなければ作り直さない）。
- 進み具合は保存先の `preload.json` で確かめます。

```json
{ "target": ["13"], "state": "done", "total": 62, "done": 62, "failed": 0, "startedAt": 1791944956576, "updatedAt": 1791944984711 }
```

- `state`: `running`（実行中。`updatedAt` が古いまま変わらなければ、中断した跡）/ `done`（範囲内を一巡した）/ `stopped`（止めた。`reason` と `message` に理由）。
- `reason`: `budget`（予算の不足）/ `blocked`（国外 IP の拒否）/ `errors`（失敗の連続など）。
- `total`: 範囲内の市区町村の数、`done`: 取得を終えた数、`failed`: 失敗した構築の数（`done` に数えない）。`failed` が残ったまま `done` になった市区町村は、次の起動でやり直します。
- 中断した構築が残した作業ディレクトリ（`tmp/`）は、次の構築を始めるときに、1時間より古いものを片付けます。

実測の目安です（2026-10-14、日本のホスト、取得元は実際の ABR。全国マスター・郵便番号・索引の約 40MB を含む）。

| 範囲 | 市区町村 | 所要時間 | ディスク使用量 |
| :--- | :--- | :--- | :--- |
| 鳥取県（`31`） | 19 | 28 秒 | 72MB |
| 佐賀県（`41`） | 20 | 41 秒（22 秒で中断して再実行） | 105MB |
| 東京都（`13`） | 62 | 73 秒 | 109MB |

1 市区町村あたり約 1〜1.5 秒、約 1〜3MB でした。ここから全国（1,898 市区町村）は 1 時間前後、数 GB と見積もれますが、**実測ではありません**。地番の多い県は大きくなる（長崎市は 1 件で約 8 秒、13MB）ので、全国を指定する前に県単位で試し、`preload.json` と使用量を見て `SORA_ADDRESS_MAX_MB` を決めてください。

### 単体ジョブの手動実行（コンテナ内）

コンテナの外のバッチなどで、特定のデータだけを準備したい場合は、同梱の `address-build.js` を直接実行できます。
```bash
# 全国マスターの構築
bun /app/address-build.js --dir /data/address --job '{"kind":"master"}'

# 郵便番号データベースの構築
bun /app/address-build.js --dir /data/address --job '{"kind":"postal"}'

# 町字逆ジオコーディング索引の構築
bun /app/address-build.js --dir /data/address --job '{"kind":"index"}'

# 東京都千代田区（131016）の段A（町字）の構築
bun /app/address-build.js --dir /data/address --job '{"kind":"city","lgCode":"131016"}'

# 東京都千代田区（131016）の段B（住居表示・地番・番地号）の構築
bun /app/address-build.js --dir /data/address --job '{"kind":"num","lgCode":"131016"}'
```

終了コード:
- `0`: 正常終了
- `1`: 取得・構築失敗
- `2`: 引数の誤り
- `3`: 国外 IP ブロック等によるアクセス拒否（HTTP 403）

## 5. 注意事項とトラブルシューティング

### 国外 IP アドレスによるアクセス制限
デジタル庁アドレス・ベース・レジストリ（ABR）の配信 CDN は、日本国外の IP アドレスからのアクセスに対して HTTP 403 を返却する場合があります。
- 国外 IP からの実行時は、エラーが検知されると指数バックオフ（cooldown）に入り、不要な再試行による負荷を防ぎます。
- API 応答としては、答えを部分的に返せる場合は `unavailable: [{ artifact: "...", message: "... HTTP 403（国外 IP からの接続は拒否されます）" }]`（`incomplete: true`）、答えようがない場合は REST の 502 `ADDRESS_DATA_UNAVAILABLE`（`retryable: false`）が返却されます。待ち時間（`SORA_ADDRESS_WAIT_MS`）までにデータが揃わなかった場合は、502 `ADDRESS_DATA_PENDING`（`retryable: true`）です。
- 国外ホスト上で Sora を運用する場合は、`SORA_ADDRESS=off` に設定するか、事前に国内ネットワークで `/data/address` を構築してマウントすることを推奨します。

### 入力表記の言い換え
入力のままでは番地・号（level 8）に届かず、データの不足でもないときだけ、言い換えた入力を試し、より深く届いた結果を採ります（届く入力には余分な処理をしません）。言い換えは、街区表記（`6街区21号` → `6-21`）、`線`・`号`・`番` の前の漢数字（`六十七番` → `67番`。`一番町` のような地名は変えない）、葦と芦の異体字（ABR の綴り `葦北郡芦北町` に合わせる）です。ABR に無い番地（街区符号が片仮名の住所、大字の無い住所など）は補えません。

### ディスク容量の枯渇
- 1 市区町村あたりのデータサイズ目安（実測。§6）:
  - 段A（町字）: 十数KB 〜 約 500KB（京都市中京区が約 500KB）
  - 段B（住居表示・地番）: 約 260KB（千代田区）〜 約 13MB（長崎市。住居表示 5.5MB + 地番 7.4MB）。より大きい市区町村は未測定
  - 全国マスター + 郵便番号 + 索引: 約 40MB（0.3MB + 18MB + 20MB）
- 予算（`SORA_ADDRESS_MAX_MB`）が小さい場合、頻繁に evict と再取得が発生する可能性があります。大都市圏を網羅的に利用する場合は 2GB〜4GB 程度の確保を推奨します。

### 出典とライセンス表示
本機能が出力する住所情報の出典は、次のとおりです：
- デジタル庁 アドレス・ベース・レジストリ: **公共データ利用規約 第1.0版（PDL1.0）**。出典の記載と、加工した旨・加工者の明記が必要です。
- 日本郵便 郵便番号データ: 著作権を主張せず自由に配布してよいとされており、出典の表示は必須ではありませんが、併記しています。
- 地番データ（ABR の地番マスター・地番マスター位置参照）: 法務省の登記所備付地図データに基づくため、デジタル庁の利用規約に加えて、**登記所備付地図データ利用規約**（法務省。G空間情報センターで公開。令和5年1月23日制定。政府標準利用規約 第2.0版に準拠）が適用されます。2026-10-14 に、デジタル庁の ABR 利用規約のページと規約の本文で確認しました。

登記所備付地図データ利用規約の要点です。
- 商用を含めて利用できます。出典を記載してください（記載例: 「出典：「登記所備付地図データ ○○市」（法務省）（URL）（○年○月○日に利用）」）。
- 加工した場合は、加工した旨を記載してください（記載例: 「「登記所備付地図データ」（法務省）（URL）を加工して作成」）。国が作成したかのような公表はできません。
- 禁止行為のひとつに、データの内容を他の情報と照合して特定の個人を識別する行為があります。**地番から所有者などの個人を特定する用途には使えません。** 本機能は住所の実在確認と座標の取得のためのもので、個人の識別は行いません。この機能を使うサービスでも、同様の用途に使わないでください。
- 地図の精度は作成時期などによって異なり、法務省はその正確性を保証しません。

MCP ツールおよび REST レスポンスの `attribution` フィールドには、ABR と日本郵便の出典と加工の明記が自動で付きます。`get_elevation` と `search_poi` の座標解決では、`geocodingAttribution` と `centerResolved.attribution` が、`search_poi` の `withAddress` では `addressAttribution` が同じ役割です。結果に地番のデータ（`numberSource: "chiban"` の住所や、地番の点を最寄りとして返した逆引き）を使ったときは、さらに法務省の登記所備付地図データの出典、加工した旨、精度の注意が付きます。結果を表示・公開する際は、必ず併記してください。記載例にある利用日（「○年○月○日に利用」）は、表示・公開する側で必要に応じて付記してください（データの時点は `dataset.updatedAt` で分かります）。

## 6. 実データ実測ベンチマーク（2026-10-14 実測値）

日本のホスト環境（Bun v1.3.3 / Linux x64）において、デジタル庁 ABR および日本郵便の最新一次データを用いて計測した実測値です。

### 1. 全国共通データの初期構築
| 成果物 | 構築所要時間 | 成果物サイズ | 備考 |
| :--- | :--- | :--- | :--- |
| `master` (全国マスター) | **358 ms** | 305 KB | 全 1,898 市区町村のコード・代表点座標 |
| `postal` (郵便番号・事業所) | **1,951 ms** | 17.5 MB | 全国の郵便番号 + 個別事業所番号 SQLite DB |
| `index` (町字代表点の索引) | **3,010 ms** | 20.3 MB | 全国の町字代表点（約 19.7 万点）を 0.01 度の格子で引く SQLite DB |

### 2. 市区町村データの初回構築（段A・段B）
| 自治体 | 段A (町字) 時間 | 段A サイズ | 段B (番地号/地番) 時間 | 段B サイズ | 種別 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **東京都千代田区** (`131016`) | 315 ms | 19.7 KB | 484 ms | 261 KB | 住居表示 |
| **東京都世田谷区** (`131121`) | 327 ms | 47.6 KB | 1,853 ms | 4.75 MB | 住居表示（大規模） |
| **札幌市中央区** (`011011`) | 345 ms | 191.9 KB | 1,442 ms | 2.09 MB | 条丁目・地番 |
| **京都市中京区** (`261041`) | 339 ms | 498.3 KB | 522 ms | 487 KB | 通り名・地番 |
| **京都府福知山市** (`262013`) | 338 ms | 43.5 KB | 2,325 ms | 6.27 MB | 郡部・広域地番 |

- **段A**: 上の 5 市区町村で 350ms 以下（目標 500ms 以下）。
- **段B**: 上の 5 市区町村で最大 2.3秒。最大規模の長崎市（住居表示 + 地番、約 56 万筆）は別の計測で 5.7〜8.2 秒、子プロセスのピークメモリは約 300MB（目標は 15 秒以内・300MB 以下）。
- 初めて使う市区町村では、これに子プロセスの起動（約 0.06 秒）と、ライブラリの読み込み（約 0.1〜0.2 秒）が加わります。全国マスター・郵便番号・索引を含む完全なコールドスタートは約 2.6 秒でした。

### 3. API 応答レイテンシ（構築済みデータ・100回試行）
| API / ツール | 平均 (avg) | 中央値 (p50) | 95パーセンタイル (p95) | 設計目標値 |
| :--- | :--- | :--- | :--- | :--- |
| `search_postal_code` (順引き) | **0.11 ms** | **0.10 ms** | **0.19 ms** | p95 20 ms 以下 |
