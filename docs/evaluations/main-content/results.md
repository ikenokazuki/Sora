# 本文の取り出しの評価

2026-10-28。ページの本文を取り出す処理（`src/html_parser.ts` の `convertHtmlToMarkdown` → `selectMainContent`）の評価です。次の 2 つを直しました。

1. **一覧・まとめのページ**: Readability が一覧のカード 1 枚や横の宣伝枠だけを本文にしたとき、同じ形の項目が並ぶ入れ物に替えます（`largestRepeatedItemList`）。
2. **表で段組みした古いページ**: レイアウト用の表を「表の本文」とみなして、ページ全体に戻していました。この戻しをやめます（`isDataTable`、`BODY_FALLBACK_MAX_READ_CHARS`）。

## 評価の方法

- **WCXB**（Web Content Extraction Benchmark、arXiv 2605.21097、CC BY 4.0、https://github.com/Murrough-Foley/web-content-extraction-benchmark）
  - 2,008 ページ・7 種類（記事・掲示板・商品・まとめ・一覧・技術文書・サービス）で、英語が中心です。
  - dev 1,497 ページで調整し、test 511 ページで判断しました。
  - 指標は `evaluate.py` の語の F1 です。小文字にして `\w+` で語に切り、正解の本文と多重集合で比べます。
- **Bevendorff ら（SIGIR 2023）の評価集**（https://github.com/chatnoir-eu/web-content-extraction-benchmark、Apache-2.0）
  - CleanEval・CETD・Dragnet・L3S-GN1・Readability・Scrapinghub などの 8 つの評価集を合わせた 3,985 ページで、2007〜2017 年ごろの英語の記事が中心です。
  - WCXB とは別の作者のものです。調整には使わず、確かめるためだけに使いました。指標は WCXB と同じ語の F1 です。
- **日本語のページ**
  - Sora がよく読む種類の検索語 20 個（公式サイトのお知らせ・予定、チケット、商品、ブログ、官公庁）の上位 2 件ずつ、取得できた 38 ページです。
  - 正解は無いので、新旧の出力を並べ、旧の出力にあった行を新が落としていないかを見ました。
- **Sora の出力**: `convertHtmlToMarkdown(html, url, 10_000_000, false, true)` の Markdown から、記号と URL を外して採点しました。
- **比べた相手**:
  - 素の Readability（Sora と同じ `@mozilla/readability` と linkedom）
  - Trafilatura 2.0.0（既定の設定）
  - rs-trafilatura 0.2.2（下の節）
- **実行**:
  - WCXB: `bun scripts/eval-wcxb.ts --data <WCXB> --split test --out <予測の JSON>` のあと、`python3 -I <WCXB>/evaluate.py --split test --results <予測の JSON> --per-type`。
  - Bevendorff らの評価集: `bun scripts/eval-wcxb.ts --bevendorff <combined の場所>`。
    - 下の表の数字は、Sora の出力の先頭のメタデータ（frontmatter）を外して採点した値です。
    - スクリプトは外さないので、全体は 0.863 になります。

## 変更前の弱いところ

WCXB（dev）では、一覧・まとめ・掲示板の 4 割前後で、本文の 3 割も取れていませんでした。

| 種類 | 件数 | 本文の 3 割も取れていない | 余計な部分が半分以上 |
|---|---|---|---|
| 掲示板 | 113 | 41% | 9% |
| 一覧 | 99 | 39% | 9% |
| まとめ | 117 | 36% | 19% |
| 商品 | 119 | 23% | 38% |
| 記事 | 793 | 3% | 3% |

一覧では、次のものを選んでいました。Readability は本文を一つの要素として取るので、リンクの多い一覧より、近くの文章の段落を選びやすいためです。

- ニュースの一覧の代わりに、「Your content on Hospitality Net?」の枠
- 番組の一覧の代わりに、話題の一覧
- レシピの一覧の代わりに、カード 1 枚

Bevendorff らの評価集では、Sora は素の Readability より大きく劣っていました（全ページの平均 0.784 対 0.851）。

- 特に L3S-GN1（古いニュース）は 0.644 対 0.913 で、精度は 0.58（素の Readability は 0.92）、再現率は 0.95 でした。
- 原因は、表があって `main`・`article` が無いページで、ページ全体に戻していたことです。段組みに表を使う古いページでは、ナビ・フッターまで本文に入っていました。

## 採用した方式

**一覧の直し**: 同じ形（タグと class）の子要素が 3 つ以上並ぶ入れ物のうち、項目の文字数の合計が最も多いものを探します。

- 16 字以下の項目はナビのラベルとして数えません。
- 項目の 6 割以上がナビのラベルなら、ナビの並びとして除きます。
- ナビ・ヘッダー・フッター・補助の領域の中は見ません。

Readability の本文が 600 字未満で、その並びに 300 字以上、かつ Readability の本文の 3 倍以上の文字があれば、並びの入れ物を本文にします。

| 案（WCXB の dev） | 全体 F1 |
|---|---|
| 変更前 | 0.7658 |
| 採用（Readability が 600 字未満のときだけ） | 0.7761 |
| 上限 1,500 字 | 0.7827 |
| 上限 3,000 字 | 0.7853 |
| 上限なし | 0.7856 |
| 3 倍を 2 倍にする | 0.7760 |
| Readability の本文を並びの前に残す | 0.7761 |

WCXB だけなら、上限なしが最も良い結果でした。ただし日本語のページでは、上限なしだと Yahoo!知恵袋の質問と回答（Readability が正しく取った約 740 字）が、横の関連の並びに替わりました。上限 600 字ではこれを防げるので、こちらを採りました。

**表の直し**: 次の 2 つを両方入れました。

- 救済の対象にする表を、見出しのある表（`th`・`thead`・`caption` があり、中に表を入れていないもの）に限ります。カレンダーや `role="grid"` は今までどおり対象です。
- `main`・`article` が無いページでページ全体に戻すのは、Readability の本文が 500 字未満のとき（予定表だけのページなど）に限ります。

Bevendorff らの評価集で比べると、片方だけでは次のとおりで、両方入れると 0.864 でした。

- 見出しのある表だけを対象にする: 0.861
- 短いときだけ戻す: 0.854

## 既知の限界

- 一覧が何種類もあるページでは、いちばん文字数の多い並びが本文とは限りません（上のローチケ）。
- 日本語の予定のページ（≠ME・=LOVE のスケジュール、ぴあアリーナの公演一覧）では、まだ予定の中身を取れていません。
- 掲示板では、Readability が「comment」などの名前の要素を消すため、投稿の本体を落とすことがあります。Readability の本文が 600 字以上だと、差し替えも起きません。
- WCXB と Bevendorff らの評価集は英語が中心です。日本語のページは、38 件を目で確かめただけです。
