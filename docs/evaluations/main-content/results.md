# 本文の取り出し（一覧・まとめ・掲示板のページ）の評価

2026-10-28。ページの本文を取り出す処理（`src/html_parser.ts` の `convertHtmlToMarkdown` → `selectMainContent`）の評価です。

Readability が一覧のカード 1 枚や横の宣伝枠だけを本文にしたとき、同じ形の項目が並ぶ入れ物に替えるようにしました（`largestRepeatedItemList`）。

## 評価の方法

- **評価集**: WCXB（Web Content Extraction Benchmark、arXiv 2605.21097、CC BY 4.0、https://github.com/Murrough-Foley/web-content-extraction-benchmark）。
  - 2,008 ページ・7 種類（記事・掲示板・商品・まとめ・一覧・技術文書・サービス）。dev 1,497 ページで調整し、test 511 ページで判断しました。
  - 英語が中心です。
- **指標**: WCXB の `evaluate.py` の語の F1 です。小文字にして `\w+` で語に切り、正解の本文と多重集合で比べます。
- **Sora の出力**: `convertHtmlToMarkdown(html, url, 10_000_000, false, true)` の Markdown から、記号と URL を外して採点しました。
- **比べた相手**:
  - 素の Readability（Sora と同じ `@mozilla/readability` と linkedom）
  - Trafilatura 2.0.0（既定の設定、nixpkgs の python3Packages.trafilatura）
- **日本語のページ**: Sora がよく読む種類の検索語 20 個（公式サイトのお知らせ・予定、チケット、商品、ブログ、官公庁）の上位 2 件ずつ、取得できた 38 ページです。新旧の出力を並べ、旧の出力にあった行を新が落としていないかを見ました（正解は無い）。
- **実行**: `bun scripts/eval-wcxb.ts --data <WCXB> --split test --out <予測の JSON>` のあと、`python3 -I <WCXB>/evaluate.py --split test --results <予測の JSON> --per-type`。

## 採用した方式

同じ形（タグと class）の子要素が 3 つ以上並ぶ入れ物のうち、項目の文字数の合計が最も多いものを探します。

- 16 字以下の項目はナビのラベルとして数えません。
- 項目の 6 割以上がナビのラベルなら、ナビの並びとして除きます。
- ナビ・ヘッダー・フッター・補助の領域の中は見ません。

Readability の本文が 600 字未満で、その並びに 300 字以上、かつ Readability の本文の 3 倍以上の文字があれば、並びの入れ物を本文にします。

dev での比較:

| 案 | 全体 F1 |
|---|---|
| 変更前 | 0.7658 |
| 採用（Readability が 600 字未満のときだけ） | 0.7761 |
| 上限 1,500 字 | 0.7827 |
| 上限 3,000 字 | 0.7853 |
| 上限なし | 0.7856 |
| 3 倍を 2 倍にする | 0.7760 |
| Readability の本文を並びの前に残す | 0.7761 |
| 表があり `main`・`article` が無いときに、ページ全体の代わりに表だけを足す | 0.7762 |

WCXB だけなら上限なしが最も良い結果でした。ただし日本語のページでは、上限なしだと Yahoo!知恵袋の質問と回答（Readability が正しく取った約 740 字）が、横の関連の並びに替わりました。上限 600 字ではこれを防げるので、こちらを採りました。表の扱いの変更は効果がほぼ無かったので入れていません。

## 日本語のページ（38 件）

変わったのは 7 件です。

- **良くなった 5 件**:
  - チケットぴあのトップ: 旧は「現在地からの距離」の絞り込みの部品 → 新は「おすすめチケット情報」の一覧
  - ヨドバシの分類ページ: 新は商品の一覧
  - アメブロのタグ「ライブレポート」: 旧は記事 1 件の抜粋 → 新は記事の一覧
  - 厚生労働省の新着情報・お知らせ一覧の 2 件: 旧は「言語切替」の案内文 → 新はお知らせの一覧
- **良し悪しが混ざる 1 件**: アメブロのタグ「ライブ」は記事の一覧が取れた一方、タグの説明文を落としました。
- **悪くなった 1 件**: ローチケの東京のページです。旧は「東京のチケットならローチケ」と施設の画像の並び → 新は飛行機の宣伝の並び。
  - 一覧が何種類もあるページで、いちばん長い並びが宣伝だったためです（既知の限界）。

## 既知の限界

- 一覧が何種類もあるページでは、いちばん文字数の多い並びが本文とは限りません（上のローチケ）。
- 掲示板では、Readability が「comment」などの名前の要素を消すため、投稿の本体を落とすことがあります。Readability の本文が 600 字以上だと、差し替えも起きません。
- WCXB は英語が中心で、日本語のページは 38 件を目で確かめただけです。
