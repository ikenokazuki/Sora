# 段落の点数（BM25）の評価

2026-10-28。見出し階層ボーナス付き BM25（`src/extractor/hierarchical_bm25.ts` の `scorePassage`）を、日本語の公開評価集で測りました。字幕の段落選びと、`legacy` のハイライトがこの点数を使います。

既定の k1 と b を 1.5・0.75 から 0.9・0.4 に変えました。あわせて、rho-select v2 の点数と、本番と同じ呼び方の rho-select が選ぶ段落も測りました。

## 評価の方法

- **評価集**: JQaRA（https://huggingface.co/datasets/hotchpotch/JQaRA。質問は JAQKET、文章は Wikipedia、CC BY-SA 4.0）。
  - dev は 1,737 問 × 候補 50 件、test は 1,667 問 × 候補 100 件です。
  - 答えを含み、問いに答えるのに役立つ候補が正解です（規則で付けたあと、AI と人で確かめたもの）。
- **測り方**: 問いごとの候補を一つのページの段落とみなし（見出しは title、IDF も候補の中で数える）、点数の順に並べて nDCG@10 と MRR@10 を出しました。
  - 同点は id のハッシュの順にしました。データの並びには正解が先に来る偏りがあるためです。
- **写した計算の確かめ**: 実験用に写した計算が本物と同じことを確かめました。
  - `scorePassage`: 最大の差 1.4e-14
  - rho-select v2 の r_it: 選ばれた 55 件すべてで `evidenceScores` と一致
- **調整と判断**: dev で決め、test で判断しました。JQaRA は文の形の質問で、Sora の実際の検索語（語を並べた形）とは違います。そのため、変えるのは test で上がり、字幕の評価（`docs/evaluations/youtube-excerpt/results.md`）で下がらないものだけにしました。
- **実行**: `bun scripts/eval-jqara.ts --data <JSONL の場所> --split test [--select]`。parquet から JSONL への変換の仕方は、スクリプトの先頭にあります。
  - `--select` は、ハイライトの選び方（`extractQueryHighlightDetails`）が選んだ段落の精度を出します。
  - 下の rho-select の数字は、v2.53.0 の時点のコードで測ったものです。

## 結果

| 方式 | dev nDCG@10 | test nDCG@10 | test MRR@10 |
|---|---|---|---|
| 変更前の `scorePassage`（k1=1.5、b=0.75） | 0.7330 | 0.4287 | 0.6655 |
| **変更後（k1=0.9、b=0.4）** | 0.7343 | **0.4476** | **0.6896** |
| (a) 語の切れ目（カタカナだけ・英数字だけの語は、前後が同じ文字種なら数えない。`termHits` と同じ規則） | 0.7141 | — | — |
| (c) NFKC と語末の長音の正規化 | 0.7327 | — | — |
| (d) ひらがなだけの語と不要語を外す | 0.7404 | 0.4275 | 0.6629 |
| (d) のうち不要語だけを外す | 0.7338 | 0.4287 | 0.6639 |
| (b) 語どうしの近さ（最小の間隔、Tao & Zhai 2007） | 0.7327 | 0.4292 | 0.6656 |
| 参考: Intl.Segmenter の語で数える素の BM25 | 0.7459 | 0.4650 | 0.7076 |
| 参考: rho-select v2 の r_it の加重和 | 0.6460 | 0.3977 | 0.6246 |
| 公開値: BM25 | — | 0.458 | — |
| 公開値: japanese-reranker-cross-encoder-xsmall-v1（約 1.07 億パラメータ） | — | 0.6136 | — |
| 公開値: ruri-reranker-small | — | 0.6453 | — |

k1 と b は、dev で (d) と組み合わせて 4 × 4 の格子を回し、いちばん良かった値です。(d) は test で効かず、変えたのは k1 と b だけです。b を小さくすると長い段落を強く罰しなくなり、候補が 100 件で長さの差が大きい test のほうが効果が大きく出ました。

字幕の評価では、変更前と変更後で同じ結果でした（held-out の現行 0.408 / 0.471、HMM 0.438 / 0.696）。

採らなかった変種:

- **(a) 語の切れ目**: 悪化しました。カタカナ・英数字の複合語の中の一致を、正しいものも含めて数えなくなるためです。この規則では、「ライブ」は「ライブラリ」に当たらなくなる一方、「ライブハウス」にも当たりません。
- **(d) ひらがなだけの語を外す**: test で効かなかったうえ、Sora の検索語には「君と見るそら」の「そら」のように、ひらがなだけの名前があります。

## rho-select v2 が選ぶ段落

本番と同じ呼び方（`extractWithEscalation`、tau=96）で選んだ段落のうち、正解の割合を見ました。同じ数を `scorePassage` の上位から取った場合と比べています。

| | 1 問あたりの選んだ数 | 正解の割合 | 1 つでも正解を選べた問い |
|---|---|---|---|
| rho-select v2（dev、1,737 問） | 2.02 | 0.330 | 0.632 |
| 同じ数を `scorePassage` の上位から | 2.02 | 0.581 | 0.832 |
| rho-select v2、tau=384（dev の 600 問） | 3.23 | 0.271 | 0.745 |
| 同じ数を `scorePassage` の上位から | 3.23 | 0.491 | 0.900 |

原因と考えられるのは次の 3 つです。

- **要件の数の上限:** 要件（問いの語）を 6 個までに絞ります。上限を 12 にすると、r_it の加重和の順位が 0.646 → 0.701 に上がりました。ただ、本番の選び方では計算が 600 問で 15 分を超えました。
- **目的の式:** 要件ごとに一番の段落を集める式なので、語が一緒に出る段落を評価しません。
- **長さの罰:** 短い段落を好みます。

置き換え先の候補として、見出し階層ボーナス付き BM25 に MMR を組み合わせた選び方（`extractQueryHighlightDetails`）も測りました。dev の 1,737 問で、選んだ数は 2.90、正解の割合 0.531、1 つでも正解を選べた問い 0.881 でした。字幕（`docs/evaluations/youtube-excerpt`）でも、チャプターの無い動画では rho-select より上でした（正解の割合 0.385 対 0.316、1 つでも正解 0.673 対 0.356）。この結果をもとに、rho-select を廃止しました（別の PR）。
