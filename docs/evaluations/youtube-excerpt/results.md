# 字幕の段落選び（チャプターの無い動画）の評価

2026-10-28。YouTube の字幕が長いときに、検索語に関係する段落を選ぶ処理（`src/services/youtube.ts` の `rankParagraphs`。`scrape`・`search_video` の `transcripts`・`search_deep` の `videos` が共用）の評価です。チャプターの無い動画では、段落ごとの BM25 の代わりに、話題のつながりを隠れマルコフモデル（HMM）で見る形に替えました。

## 評価の方法

- **動画**: Sora の動画検索（`searchYahooVideo`、YouTube に限定）で、ジャンルを散らした 20 の検索語（講義・解説・対談・ポッドキャスト・アイドルの配信・料理・ゲームなど）から集めた日本語の動画 37 本。8 分未満は除きました。説明欄にチャプターが 5 個以上ある動画が 18 本、チャプターの無い動画が 19 本です。
- **正解**: 説明欄のチャプターの時間帯。YouTube が動画ページで読み取ったチャプター（`ytInitialData` の `DESCRIPTION_CHAPTERS`）を使いました。
- **検索語**: チャプターの題名（先頭の番号と【】を除く）。「はじめに」「まとめ」などの題名、60 秒未満のチャプター、段落が 2 つ未満のチャプターは除き、1 本あたり最大 6 個を等間隔に選びました。
- **入力**: チャプターを外した段落（チャプターの無い動画を再現する）。予算は 2000 字（`search_video` の既定）。
- **分け方**: 動画単位で dev（9 本・49 問）と held-out（9 本・52 問）に分けました。パラメータは dev だけで決め、held-out で判断しました。
- **指標**:
  - **精度**: 選んだ字数のうち正解チャプターに入る割合。
  - **取れた割合**: 正解チャプターの字数のうち選べた割合。分母は「チャプターの字数」と「予算」の小さい方。
  - **1 位**: いちばん上に選んだ段落が正解チャプターに入るか。
  - **塊**: 選んだ段落がいくつの連続した塊に分かれたか。
- 字幕の本文は保存するだけで、出力していません。ケースは `eval/youtube_excerpt_cases.json`（動画 ID・時間帯・検索語）にあります。

## 結果（held-out、52 問）

| 方式 | 精度 | 取れた割合 | 1 位 | 塊 |
|---|---|---|---|---|
| 現行（段落ごとの BM25） | 0.408 | 0.471 | 0.365 | 5.1 |
| B1 隣の点数を足す（α=0.5） | 0.430 | 0.600 | 0.404 | 3.2 |
| B2 上位の前後 1 段落を足す | 0.406 | 0.587 | 0.346 | 2.7 |
| D 点数の密度が最大の区間（Dinkelbach、α=0.5） | 0.437 | 0.514 | 0.404 | 3.9 |
| E TextTiling で区切ってから加点（w=4、γ=1） | 0.418 | 0.550 | 0.365 | 4.3 |
| **C HMM（採用）** | **0.438** | **0.696** | **0.538** | 2.3 |
| F CRF（dev で学習） | 0.420 | 0.711 | 0.654 | 2.4 |
| 参考: rho-select v2 | 0.410 | 0.086 | 0.423 | 1.1 |
| 参考: 本物のチャプター付きの現行 | 0.704 | 0.972 | 0.942 | 3.8 |

B1・B2・D・E は、BM25 の既定値を変える前（k1=1.5、b=0.75）の値です。変えたあと（k1=0.9、b=0.4。`docs/evaluations/term-matching/results.md`）では、現行は 0.408 / 0.471 / 0.365、HMM は 0.438 / 0.696 / 0.538 で、ほぼ同じでした。

- **HMM と現行の差**（動画単位のブートストラップ、10,000 回）:
  - 取れた割合: +0.230（95% 信頼区間 +0.172〜+0.307、9 本すべてで改善）
  - 1 位: +0.212（+0.082〜+0.321）
  - 精度: +0.026（−0.052〜+0.099、差があるとは言えない）
- **チャプターがある場合**: HMM を使うと精度が 0.704 → 0.637 に下がりました（取れた割合は 0.972 → 0.981）。そのため、HMM はチャプターの無い動画にだけ使います。

## 採用した方式

各段落が「検索語の話題に関係あり」の状態にいる事後確率を、2 状態の HMM の前向き・後ろ向きアルゴリズムで出します（Jiang & Zhai, "Extraction of coherent relevant passages using hidden Markov models", ACM TOIS 24(3), 2006）。

- **放出:** 関係ありの状態の段落の出やすさは、関係なしの exp(β(点数/最高点 − θ)) 倍とします。点数は今までと同じ `scorePassage` です。
- **選び方:** 事後確率の高い順に予算まで選びます。事後確率 0.3 未満の段落は、検索語を含まない限り選びません。
- **パラメータ:** dev で決めました。
  - 留まる確率 q = 0.9
  - β = 2
  - θ = 0.1
  - 最初の段落の事前確率 0.1
  - しきい値 0.3。しきい値なしと比べ、dev で取れた割合が同じで、精度が少し高かったので選びました。

話題は何段落も続くのに、検索語が出るのは一部の段落だけです。今までは検索語の出た段落しか選ばず、ついでに一言触れただけの離れた段落も同じ点数で拾っていました。HMM では、検索語の出ない続きの段落が上がり、選んだ段落が 5.1 個から 2.3 個の塊にまとまりました。

実験用に写した処理と実装が同じ段落を選ぶことは、チャプターの無い動画 5 本で確かめました。

## 試して採らなかったもの

- **YouTube の自動チャプター**: 37 本のどれにも、動画ページの `ytInitialData` に `AUTO_CHAPTERS` はありませんでした。
- **CRF**: 2 状態の線形連鎖 CRF です。
  - 作り: 手がかりは定数・その段落と前後の段落の点数・前後 2 段落の最大点・検索語を含むか・前後の段落との語の重なりの 8 つ。dev の 49 問で学習し、しきい値は dev で取れた割合が最大の 0 にしました。
  - 結果: HMM と比べて、1 位は +0.115（95% 信頼区間 0.000〜+0.260）でした。精度（−0.018）と取れた割合（+0.015）は差がありません。
  - 判断: 学習が要らず、定数 4 つで済む HMM を採りました。
  - 手がかり: 学習した重みは、自分の段落の点数（0.03）より 1 つ前の段落の点数（1.86）を強く見ていました。「話題の名前が出た次の段落から、その話が始まる」という向きのある性質で、1 位を上げる手がかりになります。
- **隣の段落との語の重なりで広げる（B3）**: 現行より悪化しました（精度 0.182、dev）。
- **rho-select v2**: 選ぶ段落が少なすぎます（取れた割合 0.086）。字幕の抜粋には使っていません。

## 既知の限界

- 動画 18 本・101 問で、正解は説明欄のチャプター（作成者の区切り）です。チャプターの題名が字幕に出ない動画では、どの方式も当てにくくなります。
- 予算が狭いとき、離れた所の一言の事後確率が、本題の途中の段落より高くなることがあります。検索語の出る段落が少なく、間隔が広い場合です。
- 実行: `bun scripts/eval-youtube-excerpt.ts`。YouTube に問い合わせます。
